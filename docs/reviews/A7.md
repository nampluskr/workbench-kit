## Round 3 최종 분류 (Codex 원문 기준)

### (a) 추가 코드/문서 작업으로 해소 가능한 것
1. FR-A22의 NEWROW/STATE를 하나의 결합 시나리오로 합친다.
2. FR-A13·A17·A23(New Folder)·A24(앱 미등록 상태)의 실호스트 커버리지를 완성한다.
3. N2·N3·N4·pywebview F5 크기 검사를 별도 타임아웃을 가진 독립 네이티브 상태 시험으로 분리한다.
4. Q2의 검사를 가시성·기하·명도 대비 계산으로 교체한다.
5. 매트릭스의 인용이 실제로 그 FR과 관련 있는지까지 검증하는 의미 검사를 추가한다.
6. NFR-4 스캔 범위를 지정 파일·클래스명 밖까지 넓힌다.
7. 라이선스 본문을 상류 원본과 해시 대조 등으로 완전 검증한다.
8. `docs/checklist.md`를 FR-R3의 2분류 문언에 맞춘다(아래 (b)-2와 상충 — (b)-2가 먼저 정해져야 함).

### (b) 사람의 SPEC/DECISIONS 판단이 필요한 것
1. **VS Code와 다른 동작(기능 부재 포함)을 "divergence"로 셀지 여부.** Codex의 판단: 현재 문언 그대로면 기능 부재도 포함되어야 하므로 "정확히 1개"는 거짓이다. 선택지:
   - vscode-comparison.md에 기록된 나머지 항목들(미리보기 탭 없음, 창 밖 드래그 무반응, 기본 우클릭 메뉴 없음 등)을 실제로 구현해 VS Code와 맞춘다.
   - `NFR-3`·관련 `DECISIONS`(D-8·D-10·D-13 등)의 "정확히 1개" 문언을 사람이 개정해 이 항목들을 정식으로 받아들여진 배제/차이로 명문화한다.
2. **`FR-R3`가 2분류만 허용할지, "로직 수준 시뮬레이션"을 공식 3번째 분류로 인정할지.** 현재 SPEC·PLAN 문언은 "구분되어 있다/둘로 갈린다"로 2분류를 요구한다.
3. **`N2`·`N3`·`N4` 같은 네이티브 OS 동작에 대해 구조적/호출 수준 증거로 충분하다고 명시적으로 예외를 둘지.** 현재 공통 두 갈래 규칙과 NFR-5는 이런 예외를 문언상 허용하지 않는다.

### (c) 별도 후속 작업으로 사람의 재착수 승인이 필요한 것
1. 이미 마감된 Phase 4~6의 고정 계약(`phase4-suite.js`·`phase5-suite.js`·`phase6-suite.js`)을 다시 열어, FR-E1·E3·J1·D6·D7·G2~G4·K1~K3·P2~P4·P7의 내부 API 우회를 실제 UI 경로(닫기 버튼·Ctrl+W·찾기 위젯 입력 등)로 재작성한다.
