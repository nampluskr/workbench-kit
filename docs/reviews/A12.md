## 2. 1회차 지적과 처리

### R1-1 (Critical) — 탭 안 보기가 `stopPropagation`으로 전역 단축키를 삼킬 수 있다

- **지적**: `Ctrl+O` · `Ctrl+W` · `Ctrl+B` · `Alt+F4` · `F10` · `F11` 처리기가 `window` · `document`에
  **버블 단계**로 걸려 있다. 포커스가 탭 안 보기에 있고 그 보기가 자기 `keydown`에서
  `stopPropagation()`을 부르면 껍데기가 그 키를 못 받는다. `reserved-keys.md` §1의 "포커스와
  무관하게 껍데기가 가져간다"와 `FR-M5`를 깬다. 검사는 항상 `document.body`에서 키를 쏴서 이걸
  못 잡는다.
- **처리**: **수정했다.** 예약 키 처리기를 전부 **캡처 단계**로 옮겼다 —
  `main.ts`(`Ctrl+O/W/\/B` · `Alt+F4`), `viewstate.ts`(`F11` · `Escape`), `menu.ts`(`F10`과 열린
  메뉴 키), `contextmenu.ts`. 캡처 리스너는 이벤트가 대상 보기에 닿기 전에 돌므로 그 보기의
  `stopPropagation()`이 막지 못한다. 일치하지 않는 키에는 `preventDefault`도 `stopPropagation`도
  하지 않아 앱으로 그대로 흐른다.
- **검증**: `V2P4-CAPTURE-KEYS` — 실제로 포커스가 `.dv-content-container` 안에 있고 그 요소의
  버블 `keydown` 리스너가 `stopPropagation`을 부르는 상태에서 `Ctrl+B` · `F11` · `F10`을 쏴,
  셋 다 껍데기가 반응하는 것을 본다. 되돌리면 실패한다.

### R1-2 (Major) — 대량 닫기 취소가 작업 공간을 반쯤 비운 채로 둔다

- **지적**: `Close Editor Group` · `Close All Tabs`가 패널을 순서대로 닫다가 뒤쪽 저장 안 한
  패널에서 확인 창을 띄운다. 거기서 취소하면 앞쪽 깨끗한 패널은 이미 닫혀 있다. 명령이
  "칸 전체를 닫는다"도 "취소 시 원상태 유지"도 아니게 된다.
- **처리**: **수정했다.** `EditorController.confirmCloseAll(panels)`를 더했다 — 닫기 전에 저장 안 한
  패널을 **모두** 먼저 확인하고, 한 곳에서라도 취소하면 `false`를 반환해(그 뒤로는 아무것도
  저장 · 닫기 안 함) 호출자가 대량 닫기 전체를 중단한다. 확인을 통과한 패널만 `forceClosePanel`
  (두 번째 프롬프트 없는 raw 닫기)로 전부 닫는다. `closeAllTabsInGroup` · `closeAllTabs`가 이
  순서를 따른다.
- **검증**: `V2P4-FR-M10-CANCEL` — 깨끗한 탭 하나 + 저장 안 한 탭 둘인 칸에서 `Close Editor
  Group` → 첫 확인에서 취소 → 세 탭 다 그대로. 이어서 같은 명령을 다시 눌러 둘 다 버리면
  칸이 닫힌다.

### R1-3 (Major) — 수정자 붙은 `F11`과 메뉴 탐색 키가 예약된다

- **지적**: `viewstate.ts`의 `F11` 처리가 `Ctrl` · `Alt` · `Shift`를 안 봐서 `Ctrl+F11` 등도 Zen을
  토글한다. `menu.ts`도 메뉴가 열려 있을 때 수정자 붙은 화살표 · `Enter` · `Delete`를 먹는다.
  예약 키 계약상 목록에 없는 조합은 앱 몫이다.
- **처리**: **수정했다.** `viewstate.ts`의 `F11`은 `!e.ctrlKey && !e.altKey && !e.shiftKey`를 요구한다.
  `menu.ts`는 `F10` 분기 다음에 `if (e.ctrlKey || e.altKey || e.shiftKey) return;`을 두어, 메뉴가
  열려 있어도 수정자 조합은 앱으로 넘긴다.

### R1-4 (Major) — 좁은 창에서 하위 메뉴가 창 밖으로 나간다

- **지적**: 두 단계 하위 메뉴가 `left: 100%`로 오른쪽에 열리고 최대 480px까지 커지는데, 뷰포트
  충돌 처리도 최소 창 폭도 없다. 좁은 Electron 창에서 `Recent Folders` 등을 열면 잘린다.
  검사는 1280px 창을 쓰고 "양의 사각형이면 보임"으로 판정해 못 잡는다.
- **처리**: **수정했다.** `menu.ts` `flipClippedSubmenus()`(렌더 뒤 · 하위 메뉴 여는 mouseenter 때
  호출)가 보이는 `.menu-submenu` 중 오른쪽 끝이 `window.innerWidth - 4`를 넘는 것에
  `.submenu-flip`을 붙이고, `style.css`가 그것을 `left: auto; right: 100%`로 왼쪽에 연다.
  최소 창 폭 자체는 A11 R1-4와 같은 이유로 이번 범위 밖이다(어느 요구에도 없다).

## 3. 2회차 지적과 처리

### R2-1 (Critical) — 대량 닫기 중간 취소가 앞 탭을 "거짓 저장됨"으로 만든다

- **지적**: `confirmCloseAll`이 Save · Discard 직후 그 패널의 `isDirty`를 지운다. 탭 A를 Discard하고
  탭 B에서 Cancel하면 아무것도 안 닫히지만 A는 `isDirty: false`가 된다. 나중에 A를 닫을 때
  확인 없이 닫혀 저장 안 한 내용이 조용히 사라진다.
- **처리**: **수정했다.** `confirmCloseAll`이 `isDirty`를 **아예 건드리지 않는다.** `forceClosePanel`이
  raw 경로로 닫아 패널별 프롬프트를 건너뛰므로 지울 필요가 없었고, 중간에 지우면 뒤 패널
  취소 시 앞 패널이 거짓 상태로 남는다. Cancel이면 `false`를 반환하고 호출자가 아무것도
  바꾸지 않고 중단한다.
- **검증**: `V2P4-FR-M10-CANCEL`를 Discard-b → Cancel-c로 바꿔, 아무것도 안 닫힘 + b가 여전히
  dirty + b를 따로 닫으면 다시 묻는 것을 본다.

### R2-2 (Major) — 우클릭 메뉴가 수정자 붙은 키를 계속 먹는다

- **지적**: `menu.ts`는 고쳤지만 `ContextMenuController.handleKeydown`은 수정자를 안 본다. 캡처
  단계로 옮겨서 우클릭 메뉴가 열려 있으면 `Ctrl+Enter` 등이 앱에 닿기 전에 가로채진다.
- **처리**: **수정했다.** `handleKeydown`이 `if (e.ctrlKey || e.altKey || e.shiftKey) return;`으로 시작한다.

### R2-3 (Major) — 하위 메뉴 뒤집기가 반대쪽 밖으로 밀어낸다

- **지적**: `flipClippedSubmenus`가 1단계 File · View · Help 목록까지 오른쪽 넘침만 보고 왼쪽으로
  뒤집어, 아주 좁은 창(~350px)에서 음수 x로 밀린다.
- **처리**: **수정했다.** 2단계 `.menu-child-submenu`만 대상으로 하고(1단계 목록은 뷰포트 왼쪽
  끝에 붙어 있어 뒤집어도 소용없음), `오른쪽 넘침 && 왼쪽에 자리 있음`일 때만 뒤집는다
  (`parentRect.left - rect.width >= 4`). `.menu-child-submenu` 폭을 `200~360px`로 좁혔다. 최소 창
  폭 자체는 A11 R1-4와 같이 이번 범위 밖.

## 4. 3회차 지적과 처리 (Critical 0)

### R3-1 (Major) — 표기된 단축키가 햄버거 메뉴를 안 닫는다

- **지적**: 메뉴를 `F10`으로 연 뒤 `Ctrl+B` 등을 누르면 명령은 돌지만 메뉴가 열린 채 남는다.
  메뉴 행을 누르면 `closeMenu()`가 먼저 도는 것과 다르다. `FR-M5`("키 입력 후 화면 상태가 같은
  메뉴 항목을 눌렀을 때와 같다")를 깬다.
- **처리**: **수정했다.** `main.ts` 전역 처리기가 매칭된 단축키를 실행하기 전에
  `if (this.menu.isOpen) this.menu.closeMenu()`를 부른다.
- **검증**: `V2P4-CAPTURE-KEYS`에 "메뉴 연 상태에서 `Ctrl+B` → 메뉴 닫힘" 확인 추가.

### R3-2 (Major) — 모든 하위 메뉴에서 `Delete`가 예약된다

- **지적**: `Delete` 분기가 지우기 동작이 있는지 보기 전에 `preventDefault()`를 불러, `Color Theme`
  · `Icon Theme` 하위 메뉴에서도 `Delete`가 앱에 안 닿는다. `reserved-keys.md` §2는 `Delete`를
  `Recent Folders`에만 예약한다.
- **처리**: **수정했다.** 포커스된 행에 `secondaryAction`(지우기 버튼)이 **있을 때만**
  `preventDefault()` + 지우기. 없으면 앱으로 넘긴다.
- **검증**: `V2P4-FR-M9`에 "`Icon Theme` 하위 메뉴에서 `Delete` → `defaultPrevented === false` ·
  아이콘 테마 안 바뀜" 확인 추가.

### R3-3 (Major) — 좁은 창에서 하위 메뉴가 여전히 화면 밖

- **지적**: 2회차의 조건부 뒤집기는 왼쪽으로 밀어내는 것은 막았지만, 양쪽 다 안 맞으면 오른쪽
  넘침이 그대로 남는다.
- **처리**: **수정했다.** `flipClippedSubmenus` → `positionChildSubmenus`. 오른쪽이면 그대로, 왼쪽에
  자리 있으면 뒤집고, **둘 다 안 되면 뷰포트 안으로 명시적 `left`로 물린다**(`clampedViewportLeft`).
  최소 창 폭 · 세로 넘침은 A11 R1-4와 같이 이번 범위 밖(어느 요구에도 없음).

### R3-4 (Minor) — 수정자 검사에 `metaKey` 빠짐

- **처리**: **수정했다.** `viewstate.ts` · `menu.ts` · `contextmenu.ts`의 "맨키" · "금지 수정자"
  술어에 `metaKey`를 넣었다. `Meta+F11` 등은 앱 몫.
- **검증**: `V2P4-CAPTURE-KEYS`에 "`Meta+F11` → Zen 안 바뀜" 확인 추가.
