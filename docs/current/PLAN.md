## 읽는 법과 이 순서에 걸린 규칙

**`BRIEF ①` 같은 표기는 `BRIEF.md` 5절 완료 조건의 번호다.** 전체 9개다.

**Phase 순서는 의존 때문이다.** Phase 1이 rendered 모드와 안전한 렌더링 경로 자체를
만들고, 나머지는 그 위에 얹힌다. Phase 2(토글)가 없어도 Phase 1은 검증 스크립트로
rendered 모드를 직접 열어 판정한다. Phase 3·4는 서로 독립적이다.

**모든 Phase의 완료 조건은 두 갈래(Electron · pywebview)에서 각각 판정한다(`BRIEF ⑧`).**
그리고 매 Phase마다 `npm run typecheck`·`npm run build`·기존 `verify:*` 통과와 공통부
정적 검사(`BRIEF ⑨`)를 확인한다. Phase마다 반복해 적지 않는다.

**판정은 화면에서 한다.** 요소가 DOM에 있는지로 끝나는 판정을 쓰지 않는다 — 실측
크기·색·조상 가시성까지 본다(`.claude/rules/dockview-css.md`).

## Phase 1 — 렌더링 파이프라인

**목적** — `.md`를 안전하게 HTML로 그리는 rendered 모드 자체를 만든다.

**대응** — `BRIEF ⑦⑨` · `D-2` · `D-4` · `D-11`

**완료 조건**
- 렌더링 모듈이 `src/core/markdown/` 아래에 있고, `scripts/verify-phase3.mjs`의 공통부
  정적 검사가 이 폴더만 허용 목록으로 빼고 나머지 `src/core` 파일에는 그대로 통과한다.
- rendered 보기(식별자 `'rendered'`)로 `.md`를 열 수 있고, 그 탭의 툴팁에 `Rendered`가
  보인다. `src/presets/file-preset.ts`의 diff가 0줄이다.
- rendered로 연 `.md`의 제목·목록·GFM 테이블이 HTML 요소로 그려지고, 테이블의 실측
  크기와 선 색이 0/투명이 아니다.
- 원문 HTML 태그(예: `<b>`)는 정화 후 HTML로 그려진다.
- `<script>`, `onerror`·`onclick` 등 이벤트 속성, `javascript:` 링크가 든 `.md`를 열어도
  스크립트가 실행되지 않는다(검증 스크립트가 실행 흔적 0건을 단언).

## Phase 2 — 토글과 열기 규칙

**목적** — 사용자가 Activity Bar에서 켜고 끄며, 켜진 동안 `.md`가 rendered로 열리게 한다.

**대응** — `BRIEF ①②` · `D-1` · `D-5` · `D-6`

**완료 조건**
- Activity Bar `File Filter` 바로 아래에 호버 라벨 `Markdown Rendering` 토글이 있다.
  아이콘은 D-1의 새 SVG 두 개다 — 꺼짐은 markdown 모양 둘레의 사각형 테두리, 켜짐은
  채워진 사각형과 반전된 markdown 모양. 세 색 테마 모두에서 두 상태가 실측 색으로
  구분되고, SVG가 `currentColor`로 테마를 따른다.
- `ActivityBarController`에 더한 SVG 아이콘 경로에 마크다운·파일을 아는 코드가 없다.
- 첫 실행 시 꺼짐이다. 켜고 재시작하면 켜짐으로 돌아온다.
- 켜짐: `.md`를 트리 클릭·`Enter`·`F3`으로 열면 rendered, `F4`로 열면 editor. 열린
  `.md` 탭 안에서 `F3` → rendered, `F4` → editor로 바뀐다. 기본 열기 모드가 editor여도
  트리 클릭·`Enter`는 rendered다.
- 꺼짐: 위 동작이 v0.3과 같다(기존 `verify:*`로 확인).
- 토글을 바꿔도 이미 열린 탭의 모드는 바뀌지 않는다. `.md`가 아닌 파일은 토글과 무관하다.

## Phase 3 — 수식과 코드 강조

**목적** — rendered 화면에 수식과 코드 블록 색을 더한다.

**대응** — `BRIEF ③` · `D-3` · `D-8`

**완료 조건**
- 인라인 `$…$`와 블록 `$$…$$`가 KaTeX HTML로 그려지고, KaTeX 글꼴이 실제로 로드되며
  (`document.fonts`에 KaTeX 글꼴이 `loaded`), 수식 요소의 실측 크기가 0이 아니다.
- `katex.css`가 번들 파일로 적용된다(`document.styleSheets`에 등록, 주입 `<style>` 아님).
- ```` ```lang ```` 코드 블록에 `hljs` 클래스가 붙고, 토큰 색이 세 색 테마 각각에서
  본문 글자색과 다르다.
- Phase 1의 스크립트 미실행 단언이 수식·코드 블록 안의 악성 입력에 대해서도 통과한다.

## Phase 4 — 이미지 · 링크 · 저장 갱신

**목적** — CSP 완화와 새 호스트 브릿지가 필요한 기능을 마지막에 모은다.

**대응** — `BRIEF ④⑤⑥` · `D-7` · `D-9` · `D-10`

**완료 조건**
- `index.html` CSP에 `img-src 'self' blob:`이 있고, 그 밖의 지시문은 v0.3과 같다.
- 상대 경로 로컬 이미지가 `blob:` URL로 표시되고 실측 크기가 0이 아니다. 원격 이미지는
  표시되지 않는다.
- 상대 경로 파일 링크 → 앱 안에서 D-5 규칙대로 열림. `http(s)` 링크 → 외부 브라우저
  열기 브릿지가 그 URL로 1회 호출됨. `#…` → 해당 제목이 보이는 위치로 스크롤.
  그 밖의 스킴은 아무 것도 열지 않는다.
- 같은 파일을 editor 탭에서 저장하면 열린 rendered 탭의 내용이 저장된 내용으로 바뀐다.
  저장 전 타이핑은 반영되지 않는다.

**Phase별 공격 초점**

| Phase | 검토자에게 무엇을 깨라고 하는가 |
| --- | --- |
| 1 | 임의 마크다운(원문 HTML·속성·링크 스킴·인코딩 우회)으로 정화를 뚫어 스크립트를 실행하는 입력을 찾아라 |
| 2 | Activity Bar에 더한 SVG 경로로 임의 마크업을 주입하는 경로, 열기 규칙 표(D-5)와 실제 동작이 어긋나는 경로, 기본 열기 모드·편집 중(●) 탭과 얽혀 모드가 뜻밖에 바뀌는 경우, 토글 상태가 재시작 뒤 틀리게 복원되는 조건을 찾아라 |
| 3 | KaTeX·highlight.js 출력이 정화를 우회하게 만드는 입력, CSP 때문에 CSS·글꼴이 조용히 안 먹는데 검사는 통과하는 경로를 찾아라 |
| 4 | CSP 완화와 외부 열기 브릿지를 악용하는 경로 — 임의 스킴 실행, 경로 탈출로 폴더 밖 파일을 읽어 이미지로 띄우기, 브릿지를 렌더링 화면 밖에서 부르기를 찾아라 |

이번 버전은 **보안 경계를 여는 변경이 둘 있다** — CSP `img-src blob:` 추가(D-7)와 외부
브라우저 열기 브릿지(D-10). 검토자에게 `D-7`·`D-10`과 `BRIEF` 4절(하지 않을 것)을 함께 준다.
