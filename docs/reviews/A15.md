## 3. 1회차 지적과 처리

### R1-1 (Critical) — 화면이 스스로를 v0.1.0이라고 밝힌다

- **지적**: `package.json`이 `0.1.0`에 머물러 있고, `main.ts`가 About에 독립적으로
  `'workbench-kit v0.1.0'`을 하드코딩해 제목줄과 따로 놀 수 있다.
- **처리**: **버전 문자열 소스를 하나로 합쳤다.** `appInfoBase()` 한 함수가 제목줄과 About을
  둘 다 만든다 — 더 이상 손으로 따로 적은 두 번째 사본이 없다. 버전 **번호** 자체(당시
  `0.1.0`)는 "major·minor는 사람이 정한다"(`AGENTS.md`)는 이 프로젝트 규칙 때문에 그대로
  뒀다 — 이후 사람이 직접 `0.2.0`으로 올릴지 결정하도록 남겨 사용자에게 물었다(3절 이후
  기록).

### R1-2 (Critical) — `FR-L1` 문자 훑기가 우클릭 메뉴 · 빈 상태 · 넓은 catch-all을 놓친다

- **지적**: 우클릭 메뉴를 한 번도 열지 않는다. "빈 상태"라고 적힌 코드가 실제로는 상태
  문구만 지우고 있었다. catch-all이 리프 버튼의 속성만 본다.
- **처리**: **수정했다.** 트리 행 · 탭에 `contextmenu` 이벤트를 실제로 쏴 `.workbench-context-menu`를
  훑는다. `app.closeFolder()`를 실제로 불러 탐색기가 텍스트 0 · 자식 요소 0임을
  확인(`V2P7-FR-L1-EMPTY-STATE`, v0.1 `FR-G1`의 문언 그대로)하고 다시 연다. catch-all은
  `#workbench-root` 전체를 `TreeWalker`로 훑어 텍스트 노드 + `title`/`aria-label`/`placeholder`를
  전부 모으되, 실제 사용자 데이터·벤더 표면(`.tree-row`·`.dv-tab`·`.monaco-editor`·`.view-lines`)만
  제외한다.

### R1-3 (Critical) — `FR-L3`(한국어 파일·폴더 이름)이 한 번도 검사되지 않았다

- **처리**: **수정했다.** 두 갈래 고정 자료(fixture)에 한국어 파일 하나 · 한국어 폴더(안에
  한국어 파일 하나)를 추가했다. 새 `V2P7-FR-L3`가 트리 행의 렌더된 라벨과, 그 파일을 연 뒤의
  탭 제목·`panel.title`이 실제 이름과 정확히 같은지 본다.

### R1-4 (Critical) — `NFR-8`이 손으로 고른 11개 명령만 보고, `Alt+F4`는 실제로 눌러보지도 않는다

- **처리**: **수정했다.** 22개로 늘렸다 — 메뉴 전용 명령(Split Down · Close Editor Group ·
  Close All Tabs)은 F10 → 화살표 → Enter를 실제로 눌러 `menu.ts`의 `kbd-focused` 클래스로
  각 단계가 실제로 도착했는지 확인하는 헬퍼로 구동한다. `Exit`은 이제 더티 탭을 만들고 진짜
  `Alt+F4` 키를 쏴 확인 창이 실제로 뜨는지 보고 취소한다(v0.1 `FR-L6`에 이미 있던 안전한
  패턴 재사용). "선택한 트리 항목 확인"(Enter)은 자리 수가 1 이상이 아니라 **정확히 그
  항목**이 열렸는지 본다.
- 부수 수정: `v02-phase7-electron-runner.cjs`가 `src/hosts/electron/main.cjs`와 똑같은
  `window:close` → `confirmQuit()` 닫기 게이트를 갖췄다 — 없으면 Alt+F4의 IPC 메시지가
  갈 곳이 없어 확인 창이 영영 안 뜬다(실제 갈래 간 divergence로 잡혔다).

### R1-5 (Critical) — `WK-079` 재구현 금지 목록이 이름만 살짝 바꾸면 뚫린다

- **지적**: `class \w*Name` 정규식은 클래스 선언만 잡는다. 함수 · `const` 화살표 함수 ·
  객체 리터럴 팩토리는 그대로 통과한다.
- **처리**: **수정했다.** `combinedReimplPattern`에 `const`/`let`/`var` 바인딩 형태를
  추가했다(대소문자 무시). 실제 `src/`에 0건 오탐 확인.

### R1-6 (Major) — 회귀 경계가 스스로 모순된다

- **지적**: `PLAN.md`는 "대체 10건", `SPEC.md` 표는 22행, 검증 스크립트는 `>= 20`이라는
  세 번째 숫자를 몰래 넣고 있었다.
- **처리**: **부분 수정.** 검증 스크립트는 실제 값(22)에 정확히 고정했다. `PLAN.md`의
  "10건" 문구 자체는 사람만 고치는 문서라 손대지 않고 남겼다 — 3회차 이후 사용자에게
  물어 처분을 확정했다(4절 이후 기록).

### R1-7 (Major) — Electron 러너가 자리 준비 실패에 5분간 멈출 수 있다

- **처리**: **수정했다.** `makeFixture()`를 try/catch로 감싸 실패 시 `app.exit(1)` +
  메시지, `.then()` 체인에 `.catch()`를 추가했다.

## 4. 2회차 지적과 처리

### R2-1 (Critical) — `NFR-8`에 남은 위양성 두 곳과 빠진 명령들

- **지적**: "Open Folder"는 자리가 이미 열려 있어 `Ctrl+O` 핸들러를 꺼도 통과했다. `F6`은
  시작 포커스(트리)가 이미 "워크벤치 안"이라 F6을 꺼도 통과했다. New Tab · Show Title Bar ·
  Show Status Bar · Preset Info · About · 최근 폴더 열기 · 세로 띠 토글이 빠졌다.
- **처리**: **수정했다.** "Open Folder"는 `app.closeFolder()`로 먼저 닫고 재확인한다. `F6`은
  포커스 **정체성**을 앞뒤로 비교한다. 7개 명령을 추가해 22 → 29개로 늘렸다.

### R2-2 (Critical) — 정확히 그 금지 이름을 객체 메서드/속성으로 쓰면 뚫린다

- **지적**: `Parser() {...}`(메서드 축약), `Parser: () => {...}`(속성)는 `class`/`function`/`const`
  키워드가 앞에 없어 여전히 통과한다.
- **처리**: **수정했다.** 금지 이름 뒤에 메서드 축약 또는 속성-값 문법이 바로 오는 형태를
  잡는 세 번째 대안을 추가했다. 실제 `src/`에 0건 오탐, 지적된 두 재현 코드 모두 확인.

### R2-3 (Major) — 비교 문서 §3-2가 v0.1 이전 분할 경로를 그대로 적고 있다

- **처리**: **수정했다.** "세로 띠" 경로를 없앤 실제 경로(탭 줄 아이콘 · File 메뉴)로
  다시 썼다. 고치는 김에 같은 §3 표의 다른 행(1·3·4·5)도 확인했더니 현재 `SPEC.md`에
  없는 v0.1 전용 ID(`FR-D4`~`FR-D8`)를 접두어 없이 인용하고 있어 **`v0.1` 접두어를
  붙였다.**

### R2-4 (Major) — `PLAN.md`/`SPEC.md` 대체 건수 모순은 검증 스크립트를 고친다고 안 풀린다

- **처리**: **사람에게 넘겼다.** (4절에서 확정.)

## 5. 3회차(최종) 지적과 3회차 이후 적용한 보완

> **주의**: 아래 보완은 3회차 검토 **이후에** 적용했다 — 이 보완을 확인하는 4회차 반대
> 벤더 재검증은 한도 소진으로 실행하지 않았다. `npm.cmd test` 전건 0 failures로 회귀는
> 확인했지만, **"이 보완이 실제로 R3-1/R3-2를 닫았다"는 판정은 반대 벤더가 아니라 같은
> 구현자(Claude)가 내린 것**이다 — 이 문서 6절에서 사람 판단을 요청하는 이유다.

### R3-1 (Critical, 미확인 보완) — 정확히 그 이름을 클래스 필드/계산된 속성으로 쓰면 여전히 뚫린다

- **지적**: `static Parser = () => {...}`(클래스 필드), `['Parser']() {...}`(계산된 속성
  메서드)는 2회차 수정 뒤에도 통과한다.
- **적용한 보완**: 금지 이름에 대한 `(static )?(get|set )? NAME = (화살표|function)` 형태와
  `['NAME'](` 형태를 잡는 대안 두 개를 추가했다. 지적된 두 재현과 인스턴스 필드
  변형(`Parser = () => {}`, `static` 없이)까지 포함해 전부 확인했고, 실제 `src/`에 0건
  오탐을 확인했다(별도 스크립트, 이 검증에는 포함 안 됨 — 반대 벤더가 다시 봐야 한다).
- **알려진 한계**: getter(`get Parser() {}`)·`static` 메서드·구조분해(`const { Parser } =`)는
  검토자가 직접 확인해 이미 잡히거나(getter·static 메서드는 2회차 세 번째 대안이 이미
  잡는다) 범위 밖(단순 재-export는 그 자체로 재구현이 아니다)이라고 판정했다. "다른 이름"
  회피는 애초에 이 검사의 범위 밖으로 합의된 잔여 위험이다(`PLAN.md` 사람 결정,
  2026-09-10).

### R3-2 (Critical, 미확인 보완) — `NFR-8`이 여전히 "존재만" 확인하고, 고정 타깃 우회에 걸리지 않는다

- **지적**: 네이티브 버튼이 포커스 가능·활성 상태인지만 보고 클릭이 실제로 뭔가 하는지는
  안 본다(New Tab · New File · New Folder · Refresh · Collapse All). `F6`을 "항상 첫 번째
  칸으로 고정 이동"하게 망가뜨려도, 시작점과만 비교하는 이전 수정은 통과시킨다.
  `Shift+F6` · `Ctrl+Shift+Tab`이 빠졌다.
- **적용한 보완**:
  - **경험적으로 먼저 확인**: 실제 Electron/Chromium 빌드에서, 포커스된 네이티브
    `<button>`에 합성(untrusted) `KeyboardEvent('keydown', {key:'Enter'})`를 쏴도 그
    버튼의 클릭 핸들러가 **실행되지 않는다**(별도 Electron probe로 확인, `CLICKED_COUNT=0`).
    실제 신뢰된 키 입력과 달리, 스크립트가 합성한 이벤트로는 네이티브 컨트롤의
    Enter/Space 기본 동작이 아예 실행되지 않는다 — `FR-N3`의 네이티브 리사이즈 검사가
    이미 받아들인 것과 같은 플랫폼 한계다.
  - New File · New Folder · Refresh · Collapse All · New Tab: 구조적 확인(포커스 가능한
    네이티브 버튼)에 더해, 신뢰 여부와 무관하게 동작하는 유일한 활성화 API인 `.click()`을
    실제로 호출해 **그 결과**를 확인한다 — New File/Folder는 인라인 입력 행이 실제로
    나타나는지, Refresh는 데이터 제공자의 `getChildren`을 감싸 실제로 다시 호출되는지(호출
    안 되면 실패), Collapse All은 펼친 노드가 실제로 접히는지, New Tab은 자리 수가 실제로
    느는지.
  - `F6`: 두 번 연속 눌러 **두 번째** 이동도 실제로 일어나는지 요구한다 — "항상 고정
    요소로 이동"하는 구현은 두 번째 누름에서 자리가 안 바뀌어 실패한다. `Shift+F6`(역방향)과
    `Ctrl+Shift+Tab`(탭 역방향 순환)을 새로 추가했다.
  - `npm.cmd test` 재실행 — 29개 명령 전부(신규 포함) 두 갈래에서 실제로 통과함을 확인했다
    (구조 확인이 아니라 실제 동작 확인으로, 예를 들어 Refresh는 `getChildren` 호출 횟수가
    실제로 늘고, Collapse All은 펼친 노드가 실제로 접힌다).
- **알려진 한계**: "네이티브 버튼의 Enter/Space가 진짜로 그 클릭을 낸다"는 것 자체는
  플랫폼이 보장하는 것이지 이 스위트가 합성 키 입력으로 증명할 수 있는 것이 아니다 —
  구조(포커스 가능한 진짜 `<button>`) + 클릭 결과(`.click()`으로 낸 실제 효과)의 조합이
  이 환경에서 낼 수 있는 가장 강한 증거다.

### R3-3 (Major) — 비교 문서 §3-5의 VS Code 쪽 전제와 판정이 틀렸다

- **지적**: 이 문서가 "VS Code에는 칸 닫기 명령이 없다"고 적었는데, 실제 VS Code는 기본
  단축키 `workbench.action.closeEditorsInGroup`(Close Group)과 명령 팔레트 `View: Close
  Editor Group`을 제공한다. 그래서 v0.2가 File 메뉴에 `Close Editor Group`을 둔 것은
  "의도적 다름"이 아니라 오히려 VS Code와 **같아진** 것이다.
- **처리**: **수정했다.** §3-5의 VS Code 쪽 서술을 "칸 닫기 명령이 있다"로 고치고 공식
  참조 두 개를 인용했다. workbench-kit 쪽 판정을 "같음"으로 되돌리고, "v0.2에서 새로

## 7. 미해결 · 남은 위험

**3회 한도를 소진했고, 3회차 시점에 미해결 Critical 2건(R3-1 · R3-2)이 있었다.** 그 2건에
대해 사람이 판단할 수 있게 최선의 보완을 적용하고 `npm test` 전건으로 회귀는 없음을
확인했지만, **그 보완이 반대 벤더 기준으로 실제로 해소됐다는 확인은 받지 못했다** —
`ADVERSARIAL-REVIEW.md` 4절대로 다음 단계로 자동 진행하지 않고 사용자에게 이 상태로 Phase 7을
닫을지 판단을 요청한다.

- **R3-1 잔여 위험**: "정확히 그 금지 이름, 다른 선언 형태"라는 좁은 범위 안에서도 이론상
  더 있을 수 있는 형태(예: `Object.defineProperty`로 만든 속성)까지 전부 봉쇄했다고
  장담할 수는 없다. "다른 이름으로 회피"는 애초에 이 검사가 못 막는다고 합의된 범위다.
- **R3-2 잔여 위험**: 네이티브 버튼의 Enter/Space 활성화 자체는 이 테스트 환경(합성 이벤트)에서
  근본적으로 증명 불가능한 플랫폼 한계다(경험적으로 확인함). 구조 + `.click()` 결과 조합이
  이 환경의 사실상 상한이라고 판단했지만, 이 판단 자체를 반대 벤더가 아직 검토하지 않았다.
- **R3-4 (Major)**: `docs/vscode-comparison.md`의 §1·§2·§4·§5에 있는 v0.1-ID 접두어 누락은
  고치지 않고 남겼다. Phase 7의 완료 조건(FR-L1~L3, NFR-1~NFR-8, 전건 대조)과는 무관하지만
