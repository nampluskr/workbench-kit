What changed since round 2, mapped to round-2 findings:

1. Critical — pywebview's destroy()-triggered re-entrant events.closing was vetoed
   again, looping forever. Fix: src/hosts/pywebview/main.py's request_confirmed_close()
   now sets window._wb_close_confirmed = True immediately before every window.destroy()
   call (all three exit points: confirmed, timeout, exception). on_closing() checks that
   flag first and returns True (does not veto) when set, instead of always calling
   request_confirmed_close() again and returning False.

2. Critical — Electron's native-close catch() unconditionally closed even when
   confirmQuit() itself rejected (e.g. a save handler throwing on a real I/O failure),
   silently discarding unsaved content. Fix: src/hosts/electron/main.cjs's win.on(
   'close') catch handler no longer sets allowClose/calls win.close(); it only logs the
   error and leaves the window open (fail closed, never fail open on an error path that
   exists specifically to prevent data loss).

3. Major — File > Exit asked twice (handleExitRequest() confirmed via confirmQuit(),
   then closeWindow() reached the native close gate which confirmed again). Fix:
   src/main.ts's handleExitRequest() is now `public handleExitRequest(): void { closeWindow(); }`
   — it asks nothing itself. closeWindow() -> the 'window:close' IPC handler (Electron)
   or window.pywebview.api.close() (pywebview) -> each host's own native close gate is
   now the SINGLE place confirmQuit() is called, for both the title-bar/native close
   button and File > Exit.

4. Major — 저장 안 함 followed by resource replacement left params.isDirty: true
   surviving dockview's partial-params merge on the freshly loaded, actually-clean
   content, causing a phantom confirmation on the next close. Fix: src/core/editor.ts's
   openItem() now includes `isDirty: false` in the params object passed to
   activePanel.update() in both the FR-B3 and FR-B1 in-place-replacement branches.

5. Major — quit acceptance tests didn't exercise the real host close gates; the
   standalone Electron runner had neither the 'window:close' IPC handler nor the
   win.on('close') gate main.cjs has. Fix: scripts/phase6-electron-runner.cjs now
   duplicates that exact gate (same fail-closed catch as item 2). scripts/
   phase6-suite.js's P6-FR-L6-CANCEL now calls app.handleExitRequest() (which, per
   item 3, does nothing but closeWindow()) and waits for the round-trip through the
   real gate before checking the dialog and clicking Cancel, instead of calling
   confirmQuit() directly. P6-FR-L6-DISCARD is UNCHANGED and still calls
   editor.confirmQuit() directly — letting the real gate's affirmative path run to
   completion would tear down the very host process running the test harness.
   pywebview needed no runner change: its --phase6-test mode installs the real
   events.closing/on_closing gate unconditionally (not only in non-test runs), so
