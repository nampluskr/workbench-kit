# 공통 코어 — 리소스 종류를 아는 코드가 새는 사고를 막는다

이 규칙이 막는 사고: 껍데기 안에 "파일이란 무엇인가"를 아는 코드가 들어와, 다음 앱이
같은 껍데기를 못 쓰게 되는 것. 한 번 새면 `FR-I1`의 **공통 코어 diff 0줄**이 조용히
깨지고, 그 사실이 검사에는 통과로 남는다.

**대상 경로** — 공통 코어(껍데기)에 해당하는 모든 소스. 앱·프리셋·시험 코드는 제외.

## 하지 않는다

- 확장자 → 아이콘·언어·보기 종류 대응표를 둔다 (`FR-Q3` · `NFR-1`)
- 파일·폴더·터미널·세션이라는 낱말로 분기한다 (`INTENT.md` 3절 · D-4)
- 파일을 만들거나 이름을 바꾸거나 지운다. 껍데기는 장치만 준다 (D-30 · D-22)
- 저장을 한다. 껍데기는 ● 표시와 확인 창까지다 (D-18 · `FR-P7`)
- 앱에게 탭·칸을 만들거나 닫거나 옮기는 수단을 연다 (`FR-I8` · C-9)
- 갈래(Electron · pywebview) 이름으로 분기하는 빌드 설정을 만든다 (D-25 · `NFR-2`)

## 판단이 서지 않으면

`docs/current/INTENT.md` 3절과 대조한다. 어긋나면 혼자 맞추지 말고 멈추고 보고한다.
