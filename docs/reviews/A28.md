## 유효하지 않은 지적과 반박 근거

- #3(Find 클릭 시 입력값 손실)은 이 diff가 새로 만든 결함이 아니다. `src/core/tree.ts:830-836`의 기존 `Ctrl+F` 핸들러가 이미 무조건 `openFindWidget()`을 호출하고, Refresh/Collapse All 버튼도 각각 `refresh()`/`collapseAll()`을 통해 같은 `render()` 재호출 경로를 이미 타고 있었다(둘 다 이 세션 이전부터 존재). `render()`는 항상 `promptState.initialValue`로 입력 필드를 다시 그리며, 타이핑 중 값을 별도 상태로 동기화하는 `input` 리스너가 원래 없다(`tree.ts:1508-1533`에 `keydown`만 있고 `input`은 없음). 따라서 Find 버튼은 이미 존재하던 손실 경로에 진입점 하나를 더한 것일 뿐, 리팩토링 규정(3절)의 "동작이 바뀌지 않았나" 기준으로 봐도 관측 가능한 새로운 사용자 동작 차이가 아니다. `src/core/tree.ts`를 고치는 것은 이번 요청("검색 아이콘 추가")의 범위 밖이라 손대지 않았다.

## 미해결 · 남은 위험

- Explorer 최소 폭(160px)에서의 클리핑은 4개 액션 때부터 이미 알고 있던 채무이고, 5번째 액션으로 조금 더 나빠졌다. 실측·MIN 조정은 사용자 판단이 필요하다.
- `promptState` 타이핑 중 데이터 손실(#3의 근본 원인)은 `tree.ts`의 기존 결함으로 남아 있다. 이번 범위에서 고치지 않았고, 필요하면 별도 요청으로 다뤄야 한다.
- Codex 2회차 실행 중 `verify:phase3`를 자체 sandbox에서 재현하려다 Vite 임시 설정 파일 쓰기가 `EPERM`으로 막혔다(코드 결함 아님, Codex의 읽기 전용 sandbox 제약). 이 세션 자체의 `npm run verify:phase3`·`npm run verify:dist`는 별도로 정상 통과했다(본문 기록 참조).
