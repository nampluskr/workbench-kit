# VS Code 대조 기준 문서

> 작성: Phase 7 (WK-038) · FR-R2 · NFR-3의 완료 조건을 충족하는 정식 기준 문서.
> `docs/refs/ui-vscode-mapping.md`(참조 메모, tab-explorer의 의도 읽기)와는 역할이
> 다르다 — 여기는 **VS Code를 왼쪽 열에 놓고**, workbench-kit이 채택한 동작을
> 오른쪽 열에서 대조한다. 다섯 영역(탐색기·탭·분할 영역·선택과 포커스·키보드/마우스
> 조작) 전부를 다룬다.
>
> **2026-09-09 개정** (Phase 7 A7 리뷰): 이전 판은 "의도적으로 다르게 둔 동작은
> Zen 모드 하나뿐"이라 주장했다. 반대 벤더 검토에서 미리보기 탭 부재·창 밖 드래그
> 무반응·기본 우클릭 메뉴 부재·Welcome View 미채택도 "구현 방식만 다르고 사용자
> 결과는 같다"가 아니라 **같은 조작에서 실제로 다른 결과**가 난다는 지적을 받았고,
> 사람이 확인 후 받아들였다(NFR-3 개정). 아래는 그 판단을 반영해 divergence로
> 다시 표시한 판이다 — "같음"이 아닌 행은 전부 **의도적 다름**이다.
>
> 각 행의 workbench-kit 열은 `docs/current/SPEC.md` 1절의 FR 번호로 뒷받침된다 —
> 새로 주장을 만들지 않고 이미 판정된 요구를 그대로 대조한다.

## 1. 탐색기 (Explorer)

| # | VS Code 동작 | workbench-kit 동작 | 구분 |
| --- | --- | --- | --- |
| 1 | Explorer는 Primary Side Bar 안의 뷰 하나다. 폴더를 열면 그 폴더가 트리 루트가 된다 | 사이드바에 탐색기 트리 하나만 있다. 폴더 열기(`Ctrl+O`)로 트리 루트가 그 폴더가 되고, 이전 루트는 사라진다 (FR-A1) | 같음 |
| 2 | 트리 안에서 상위 폴더로 "루트를 바꾸는" 수단은 없다 — 루트는 항상 "폴더 열기"로만 바뀐다 | 트리 조작만으로 루트를 바꿀 수단이 0개다. 루트는 폴더 열기로만 바뀐다 (FR-A15) | 같음 |
| 3 | 폴더 앞 화살표(twistie)로 펼침/접힘, 들여쓰기 안내선으로 깊이를 표시 | 동일 — twistie로 펼침/접힘(FR-A3·A4), 들여쓰기 안내선 렌더 (D-9) | 같음 |
| 4 | 뷰 제목줄에 New File · New Folder · Refresh · Collapse All 등의 View Actions | Collapse All · Refresh 둘은 껍데기가 제공하고(FR-A20~A22), New File·New Folder는 앱이 꽂을 때만 나타난다(FR-A23·A24) — 앱이 아무것도 꽂지 않으면 아이콘 정확히 2개 | 같음 (제공 방식은 VS Code의 "확장이 액션을 더한다"와 동일한 확장점 구조) |
| 5 | Explorer가 비어 있으면(폴더 미개봉) Welcome View로 "Open Folder" 버튼을 안내 | 폴더를 아직 안 열었으면 트리 영역이 완전히 빈 면 — 안내 문구도 버튼도 없다 (FR-G1) | **의도적 다름** — 안내·버튼이 있는 화면과 완전히 빈 화면은 같은 상황(폴더 미개봉)에서 사용자가 보는 결과가 다르다. Welcome View를 채택하지 않기로 한 것은 SPEC의 결정(D-20)이지만, 그 결과 자체는 VS Code와 다른 동작이다 |
| 6 | 새로고침해도 펼침 상태와 선택은 유지된다 | 동일 — 새로고침 시 펼침 상태와 선택 항목이 그대로 유지된다 (FR-A22) | 같음 |

## 2. 탭 (Tabs)

| # | VS Code 동작 | workbench-kit 동작 | 구분 |
| --- | --- | --- | --- |
| 1 | 탐색기에서 파일을 한 번 클릭하면 미리보기 탭(제목 기울임)으로 열려 다음 파일 선택 시 대체된다. 더블클릭하거나 편집하면 고정 탭이 된다 | 미리보기 탭·고정 탭 구분을 두지 않는다 — 트리에서 고르면 항상 활성 탭의 내용이 바뀔 뿐 탭 개수는 늘지 않는다(FR-B1). 새 탭은 `+`를 눌러야만 생긴다 | **의도적 다름** — 탭이 저절로 불어나는 것을 막는다는 목적은 같지만, VS Code는 미리보기/고정이라는 탭 상태 둘을 두고 workbench-kit은 "선택은 항상 현재 탭에서 연다"는 규칙 하나로 대체했다(`docs/refs/vscode-ui-reference.md` 3절). 이미 열린 탭이 다른 파일로 조용히 바뀐다는 사용자 결과 자체가 미리보기 탭 방식과 다르다(FR-B1~B3, D-5) |
| 3 | 탭 오른쪽에 닫기 버튼(×). 닫으면 이웃 탭이 활성화 | 동일 (FR-C3, D-10) | 같음 |
| 4 | 그룹의 마지막 탭을 닫으면 그룹이 사라지고(다른 그룹이 있으면) 남은 그룹이 공간을 나눠 가짐. 마지막 그룹이면 빈 그룹으로 남는다 | 동일 (FR-C4, D-26) | 같음 |
| 5 | 같은 탭 바 안에서 드래그로 순서 변경 | 동일 (FR-C5, D-10) | 같음 |
| 6 | 다른 그룹으로 드래그하면 이동, 뷰는 다시 만들어지지 않는다 | 동일 (FR-C6, FR-E2) | 같음 |
| 7 | 편집기 가장자리로 드래그하면 그 방향으로 분할되어 새 그룹 생성 | 동일 (FR-C7, D-13) | 같음 |
| 8 | 탭을 창 밖으로 드래그하면 새 창(분리된 편집기 창)이 생긴다 | 창 밖으로 드래그해도 아무 일도 일어나지 않는다 — 창 분리·새 창 없음 (FR-C8) | **의도적 다름** — 같은 드래그 조작에서 VS Code는 새 창을 만들지만 workbench-kit은 아무 결과도 내지 않는다. 여러 창을 만드는 기능 자체를 두지 않기로 한 결정(D-13)의 결과다 |
| 9 | 탭 우클릭에 Close · Close Others · Split 등 컨텍스트 메뉴 항목이 기본 제공 | 기본 상태에서 탭 우클릭 메뉴 요소 0개 — 앱이 정의하고 켜야만 나타난다 (FR-C9, FR-G5, D-22) | **의도적 다름** — 같은 우클릭 조작에서 VS Code는 기본 메뉴가 뜨지만 workbench-kit은 앱이 켜기 전까지 아무것도 뜨지 않는다. D-22의 "장치는 껍데기, 내용은 앱" 재구성 결과다 |

## 3. 분할 영역 (Split panes / Editor Groups)

| # | VS Code 동작 | workbench-kit 동작 | 구분 |
| --- | --- | --- | --- |
| 1 | 편집기 영역은 좌우(`Ctrl+\`)·상하 모두 분할 가능한 2차원 격자, 개수 제한 없음 | 동일 — 좌우·상하 모두 분할 가능, 개수 제한 없음(FR-D6, FR-D7). dockview-core(2021, VS Code에서 나온 검증된 격자 구현)를 그대로 사용 (D-8, D-24) | 같음 |
| 2 | 그룹 오른쪽 위 아이콘(Split Right 등)·세로 띠·명령 팔레트 등 여러 경로로 분할 가능 | 탭 줄 아이콘·세로 띠·View 메뉴 세 경로 모두 같은 결과 (FR-D1~D3, D-11) | 같음 |
| 3 | 칸 사이 경계를 드래그하면 인접한 두 그룹의 크기가 반대로 바뀜 | 동일 (FR-D4) | 같음 |
| 4 | 그룹 자체를 드래그해 격자 안 위치를 바꿀 수 있음 | 동일 (FR-D5) | 같음 |
| 5 | 그룹을 "닫기"하는 별도 명령은 없다 — 탭을 모두 닫으면 그룹이 사라진다(마지막 그룹 제외) | 동일 — 세로 띠·View 메뉴·우클릭 어디에도 "칸 닫기/삭제" 항목 0개(FR-D8, D-26) | 같음 |
| 6 | 그룹을 창 밖으로 드래그하면 별도 창(Floating/새 창)으로 분리 가능 | 지원 안 함 — §2의 8번과 같은 이유 (D-13) | **의도적 다름** — §2-8과 같은 결정(D-13)의 그룹 단위 결과 |

## 5. 키보드/마우스 조작 (Keyboard & Mouse operations)

| # | VS Code 동작 | workbench-kit 동작 | 구분 |
| --- | --- | --- | --- |
| 1 | `Ctrl+O`로 폴더/파일 열기, `Ctrl+W`로 탭 닫기 | 동일 (FR-A1, FR-N6b) | 같음 |
| 2 | `Ctrl+\`로 편집기 분할 | 동일 — `Ctrl+\`가 그대로 좌우 분할을 실행한다(`src/main.ts`의 전역 키 처리, FR-D1~D3). 메뉴·아이콘 경로도 같은 결과를 낸다. 정확한 키 조합 전체 목록은 `docs/reserved-keys.md`가 정본 | 같음 |
| 3 | 세로 띠·탭 줄의 모든 버튼이 네이티브 `<button>`이라 `Tab`으로 포커스, `Enter`/`Space`로 활성화 가능 | 동일 (NFR-7) | 같음 |
| 4 | **`F11`로 전체화면 전환** — 운영체제 창 자체가 최대화되며, 메뉴 바까지 포함해 모든 UI 크롬이 사라진다. 다시 `F11`로 복귀 | **`F11`로 Zen 모드** — 창 크기는 그대로 두고 상단 바·세로 띠·탐색기·경계·하단 바만 감추고 **탭 줄과 보기 영역은 남긴다**. `F11` 또는 `Escape`로 복귀 (FR-F5·F6, D-12) | **의도적 다름 (Zen 모드)**. 창 상태를 건드리면 두 갈래(Electron·pywebview)에서 전체화면 API의 동작이 달라질 위험이 있고, 탭 줄까지 감추면 멀티터미널에서 탭 사이를 오갈 수단이 단축키뿐이 되므로 의도적으로 다르게 두었다 (D-12) |
| 5 | 마우스 우클릭 컨텍스트 메뉴가 트리·탭·편집기 각지에 기본 제공 | 기본 꺼짐 — 앱이 항목을 정의하고 켜야만 나타남 (FR-G5·G6, D-22) | **의도적 다름** (§2-9와 같은 결정 D-22) |
| 6 | 상단 바 햄버거/메뉴 바에서 `F10`으로 메뉴를 열고 화살표+Enter로 탐색 | 동일 — `F10`으로 메뉴 열기/닫기, 화살표로 항목·카테고리 이동, `Enter`로 실행 (FR-R1, WK-031) | 같음 |

## 이 문서를 어떻게 읽나

- "같음"은 VS Code가 실제로 그렇게 동작하고, 같은 조작에서 workbench-kit도 SPEC
  판정상 같은 사용자 결과를 낸다는 뜻이다.
- **"의도적 다름"은 같은 조작(또는 같은 상황)에서 VS Code와 workbench-kit이 사용자에게
  다른 결과를 낸다는 뜻이다.** 기능을 아예 두지 않기로 한 것(예: 다중 창, Welcome
  View)도 포함한다 — "그 조작을 하면 VS Code에서는 A가 일어나는데 여기서는 A가
  일어나지 않는다"는 것 자체가 다른 결과이기 때문이다(NFR-3, 2026-09-09 개정).
  각 행에 근거가 된 결정(D-n)을 함께 적는다.
- 이 문서 전체의 "의도적 다름" 행: §1-5(Welcome View), §2-1(미리보기·고정 탭
  없음, D-5), §2-8·§3-6(창 밖 드래그 무반응, D-13), §2-9·§5-5(기본 우클릭 메뉴
  없음, D-22), §5-4(Zen 모드, D-12). 그 밖의 모든 행은 "같음"이다.
