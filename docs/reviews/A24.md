**#2 수정 내용**
- `src/presets/file-preset.ts`의 `save()`가 CP949 파일(`legacy`)이면 쓰지 않고 `false`를
  돌려준다. 확인 창의 `Save`도 실패로 처리되어 탭이 닫히지 않는다.

## 유효하지 않은 지적과 반박 근거

**#1 probe 실패 시 열기**
- 의도한 설계다(D-15 계획의 "probe가 안 되면 기존대로 열어 탭이 원인을 보인다").
  R3의 거부 대상은 "바이너리로 판정된 파일"이다. 판정할 수 없는 파일은 거부 대상이
  아니다.
- 파일이 잠겼거나 사라진 경우, 탭 안의 오류 문구(`Unable to open ...: <원인>`)가 원인을
  그대로 보여 준다. 일괄 거부하면 "binary file"이라는 틀린 이유를 보이게 된다.
- 호스트에 probe가 없는 경우(검사용 스텁 등)에도 v0.3 이전 동작을 유지한다.
- 이 경로로 바이너리가 열려도 탭 안의 읽기 단계가 NUL·디코드 오류로 막아 내용이 에디터에
  들어가지 않는다.

**#3 확인 창 대기 중 요청 순서**
- 확인 창(`.workbench-confirm-overlay`)은 창 전체를 덮는 모달이다. 대기 중에는 트리나
  메뉴를 클릭할 수 없다.
- 트리로 들어온 요청은 기존 `pendingOpenEntry`가 하나로 합쳐, 확인 뒤에는 마지막 요청만
  연다.
- 남는 경로는 전역 단축키(`Ctrl+O`)로 다른 파일을 확정 탭으로 여는 것뿐이다. 이 경우에도
  확인한 A는 preview 자리만 쓰므로 B를 덮지 않는다.
- 이 흐름은 D-15 이전부터 있던 dirty preview 확인 규칙(A9)이다. D-15의 순번은 비동기
  판별을 기다리는 동안의 역전만 막는다.

**#4 이름 바꾸기로 `.pdf`가 된 열린 탭**
- D-15는 "파일을 탭으로 여는" 규칙이다. 이미 열린 탭의 내용은 텍스트로 읽힌 것이고,
  이름 바꾸기는 내용을 바꾸지 않는다.
- 탭을 닫으면 편집 중인 내용을 잃거나 저장을 강요한다. 옛 경로에 남기면 저장할 때 옛
  파일이 다시 생긴다(D-14의 배제한 대안).
- 따라가게 두는 것이 사용자 데이터에 가장 안전하다. 새로 여는 요청에는 확장자 검사가
  그대로 적용된다.

## 미해결 · 남은 위험

- Critical은 없어 재검증 실행은 하지 않았다(1/3 사용).
- #1·#3·#4는 위 근거로 고치지 않았다. 사용자가 다르게 판단하면 다시 연다.
- 모든 지적이 소스 추적으로 나온 것이다. 검토자는 실행 검사를 하지 않았다.
