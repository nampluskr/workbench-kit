## 미해결 · 남은 위험

- **#5(3회차 Critical)의 수정은 반대 벤더로 재검증되지 않았다.** `ADVERSARIAL-REVIEW.md` 4절의 "Critical을 수정했으면 같은 반대 벤더 검토를 한 번 더 실행해 해소를 확인한다"를 지키지 못했다 — 이 검증 대상의 실행 3회 한도(§4)를 이미 다 썼기 때문이다. 대신:
  - 수정 자체는 #1·#3과 정확히 같은 패턴(확인 resolve 후 재검사)이고, `npm run typecheck`·`npm run build` 통과했다.
  - `scripts/verify-explorer-delete-electron.cjs`에 이 정확한 시나리오를 재현하는 새 테스트를 추가했다 — 실제 Folder Tabs UI 대신 `tree.setRoot()`를 확인창이 열린 도중에 직접 호출해 "대상이 트리의 라이브 루트가 됨"을 재현하고, 삭제가 차단되는지 확인한다. 23개 단언 전부 통과(Electron 실제 런타임, 실제 `fs-ops.cjs`).
  - 그럼에도 이 테스트는 실제 Folder Tabs UI 조작(탭 전환 키보드 경로)을 거치지 않고 `tree.setRoot()`로 같은 상태를 직접 만든 것이라, Folder Tabs 쪽 실제 전환 로직(`activateFolderTab`의 비동기 경합 등)까지 통과하는 완전한 end-to-end 재현은 아니다.
  - **사용자 판단**: 위 내용을 그대로 보고했고, 사용자가 "이대로 완료 처리해줘"로 확인했다(2026-09-25). 반대 벤더의 독립적 재확인 없이 코드 수정 + 회귀 테스트만으로 완료 처리하는 것에 대한 명시적 승인이다.
- #4(비활성 Folder Tab)는 의도적으로 범위 밖에 남겨뒀다 — 재발하면 별도 요청으로 다룬다.
- Python `delete_path`의 NTFS 정션(junction) 안전성은 3회차에서 직접 답을 받지 못했다(모델이 대신 #5를 찾아 보고하고 라운드를 마쳤다) — 이 환경에 정션 생성 권한이 없어 실기 검증도 못 했다. 코드는 `os.path.islink()`를 먼저 확인해 심볼릭 링크는 안전하지만, **정션까지 안전한지는 미확인 상태**로 남는다.
