# VS Code UI 요소 설명 (용어 사전)

> 참조 메모 · 작성일: 2026-09-07
>
> 이 문서는 스키마 문서(`docs/`)가 아니라 `refs/`의 참조 자료다. VS Code 자체의 UI
> 요소를 용어와 함께 설명한다. 목적은 두 가지다.
>
> 1. 껍데기 화면을 이야기할 때 쓸 공통 용어를 정한다.
> 2. 사용자가 미처 몰랐던 VS Code 요소를 그 명칭으로 다시 살펴보고, 이 프로젝트에
>    넣을지 뺄지를 재검토한다.
>
> 앞선 `tab-explorer-templates`가 이 요소들을 어떻게 쓰고 있었는지 —— 즉 사용자의
> 의도를 읽는 근거 —— 는 [`ui-vscode-mapping.md`](ui-vscode-mapping.md)에 있다.
>
> 출처: VS Code 공식 문서 User Interface(code.visualstudio.com/docs/getstarted/userinterface)와
> Extension API UX Guidelines(code.visualstudio.com/api/ux-guidelines/overview) 기준.
> 각 항목 끝의 "이 프로젝트" 표시는 참고용 잠정치이며, 확정은 사람이 한다. 그 값의
> 상당수는 앞선 `tab-explorer-templates`에서 무엇이 쓰이고 무엇이 안 쓰였는지를
> 관찰해 옮긴 것이다. 그것은 사용자의 의도를 읽는 근거일 뿐 채택 근거가 아니다 —
> 채택 여부는 VS Code를 기준으로 다시 판단한다.

## 1. 레이아웃 파트 (화면의 큰 조각)

VS Code는 창을 아래 파트로 나눈다. 대부분 켜고 끌 수 있다.

| 파트 | 영문 | 무엇인가 | 이 프로젝트 |
| --- | --- | --- | --- |
| 제목 표시줄 | Title Bar | 창 맨 위. 메뉴 바·창 제목·창 버튼(최소화/최대화/닫기)을 담는다 | 사용 |
| 메뉴 바 | Menu Bar | File/Edit/View … 드롭다운 메뉴 모음. Title Bar 안에 들거나 별도 줄 | 사용(File/View/Help로 축소) |
| 활동 표시줄 | Activity Bar | 맨 왼쪽 세로 띠. 사이드 바에 어떤 뷰를 띄울지 고르는 아이콘 모음 | 사용(전환 버튼 대부분 제거) |
| 기본 사이드 바 | Primary Side Bar | 활동 표시줄이 고른 뷰가 뜨는 세로 영역. 보통 왼쪽. 탐색기가 여기 있다 | 사용 |
| 보조 사이드 바 | Secondary Side Bar | 오른쪽에 뷰를 하나 더 띄우는 영역. 뷰를 좌우로 나눠 볼 때 씀 | 미사용 |
| 편집기 영역 | Editor Area | 파일이 열리는 가운데 넓은 영역. 여러 편집기 그룹으로 나뉜다 | 사용 |
| 패널 | Panel | 편집기 아래 가로 영역. 터미널·문제·출력·디버그 콘솔이 여기 뜬다 | 미사용(터미널은 탭으로) |
| 상태 표시줄 | Status Bar | 맨 아래 가로 줄. 경로·언어·줄/열·인코딩 등 상태 항목 | 사용(최소 항목만) |

주의: VS Code의 "Panel"은 아래쪽 가로 영역을 가리키는 고유 명칭이다. 흔히 말하는
"패널(어떤 창 영역)"과 다르니 용어를 섞지 않는다.

## 2. 사이드 바 안의 구성 (뷰 체계)

사이드 바에 들어가는 내용물은 계층이 있다.

| 요소 | 영문 | 무엇인가 | 이 프로젝트 |
| --- | --- | --- | --- |
| 뷰 컨테이너 | View Container | 활동 표시줄 아이콘 하나가 여는 묶음. 그 안에 여러 뷰가 들어감 | 탐색기 하나만 |
| 뷰 | View | 사이드 바/패널에 뜨는 개별 패널. 접었다 펼 수 있다. 예: 탐색기, 검색 결과, 소스 제어 | Explorer만 |
| 트리 뷰 | Tree View | 뷰 안에 계층 목록을 그리는 방식. 탐색기의 파일 트리가 대표 | 사용(파일 트리) |
| 뷰 툴바 / 뷰 액션 | View Toolbar / View Actions | 뷰 제목줄 오른쪽 아이콘들. 예: 새 파일, 새로고침, 모두 접기 | 사용 |
| 환영 뷰 | Welcome View | 뷰가 비었을 때(폴더 미개봉 등) 보여주는 안내·버튼 화면 | 재검토 여지 |
| 배지 | Badge | 활동 표시줄 아이콘에 붙는 숫자·점 표시. 예: 소스 제어 변경 개수 | 미사용 |

재검토 여지: "환영 뷰"는 폴더를 열기 전 빈 상태에서 무엇을 눌러야 하는지 알려주는
자리다. BRIEF 완료 조건의 "빈 상태" 시나리오와 맞물린다.

## 3. 편집기 관련 세부

| 요소 | 영문 | 무엇인가 | 이 프로젝트 |
| --- | --- | --- | --- |
| 편집기 | Editor | 파일 하나를 여는 화면. 코드·텍스트·이미지·렌더 결과 등 | 사용(읽기 전용 보기) |
| 편집기 그룹 | Editor Group | 편집기를 담는 칸. 화면을 나누면 그룹이 여러 개가 된다 | 사용 |
| 편집기 분할 | Split Editor | 편집기 영역을 좌우/상하로 나눠 여러 그룹을 만드는 것 | 사용(좌우) |
| 탭 | Tab | 그룹 안에 열린 편집기 하나. 제목과 닫기 버튼(×)을 가짐 | 사용 |
| 편집기 액션 | Editor Actions | 그룹 오른쪽 위 아이콘. 분할·더보기 등 | 사용(분할) |
| 미리보기 탭 | Preview Tab | 한 번 클릭으로 잠깐 여는 탭(제목이 기울임). 다른 파일을 열면 대체됨 | 미사용 (D-5) |
| 고정 탭 | Pinned Tab | 실수로 닫히지 않게 고정한 탭 | 미사용 (D-5) |
| 탐색 경로 | Breadcrumbs | 탭 아래 줄. 파일의 폴더 경로·문서 안 위치를 따라 이동 | 미사용 |
| 미니맵 | Minimap | 편집기 오른쪽의 문서 축소 지도 | 미사용 |
| 여백/거터 | Gutter | 편집기 왼쪽 여백. 줄 번호·접기 화살표·표시가 뜨는 곳 | 부분(코드 뷰어 줄 번호) |
| 들여다보기 | Peek View | 정의/참조를 현재 자리에서 작은 창으로 겹쳐 보는 것 | 미사용 |
| 호버 | Hover | 요소 위에 마우스를 얹으면 뜨는 설명 말풍선 | 재검토 여지 |

정해짐: "미리보기 탭"과 "고정 탭"은 두지 않는다(D-5). 둘 다 탭이 저절로 불어나는
것을 막으려는 장치인데, 이 프로젝트는 "탐색기 선택은 현재 탭에서 열고, 새 탭은
사용자가 추가할 때만 생긴다"는 규칙 하나로 같은 문제를 푼다. 탭에 두 가지 상태를
더하지 않는다.

## 4. 상호작용 · 오버레이 요소

화면에 상주하지 않고 필요할 때 떠오르는 요소들.

| 요소 | 영문 | 무엇인가 | 이 프로젝트 |
| --- | --- | --- | --- |
| 명령 팔레트 | Command Palette | `Ctrl+Shift+P`. 모든 명령을 이름으로 찾아 실행하는 검색창 | 미사용 |
| 빠른 선택 | Quick Pick | 화면 위쪽에 뜨는 목록 선택창. 파일 열기(`Ctrl+P`) 등이 이 형태 | 미사용 |
| 알림 | Notification | 오른쪽 아래에 잠깐 뜨는 메시지(정보·경고·오류·진행) | 재검토 여지 |
| 컨텍스트 메뉴 | Context Menu | 마우스 우클릭으로 뜨는 메뉴 | 재검토 여지 |
| 상태 표시줄 항목 | Status Bar Item | 상태 표시줄에 놓는 개별 버튼/표시 | 사용(경로 등) |
| 진행 표시 | Progress | 오래 걸리는 작업의 진행 막대/회전 표시 | 재검토 여지 |
| 모드 라인 / 퀵 인풋 | Quick Input | 한 줄 값을 입력받는 작은 입력창 | 미사용 |

재검토 여지: "알림"과 "진행 표시"는 실패 상황·긴 작업을 사용자에게 알리는 표준
자리다. BRIEF 완료 조건의 "실패 상황" 시나리오와 연결해 최소한만 채택할지 볼 수 있다.

## 5. 확장(Extension)에서 오는 개념 (참고)

Medium 글의 원 맥락은 확장 API다. 껍데기가 확장 체계를 만들지는 않지만, 용어가
겹치므로 참고로 둔다.

| 요소 | 영문 | 무엇인가 | 이 프로젝트 |
| --- | --- | --- | --- |
| 웹뷰 | Webview | 편집기/뷰 자리에 임의의 HTML 화면을 띄우는 것. 커스텀 UI에 씀 | 개념적으로 관련(보기 = 갈아끼우는 HTML) |
| 워크스루 | Walkthrough | 처음 쓰는 사람을 위한 단계별 안내 화면 | 미사용 |
| 커스텀 에디터 | Custom Editor | 특정 파일 형식을 전용 화면으로 여는 편집기 | 개념적으로 관련(프리셋의 보기 제공자) |

참고: workbench-kit의 "탭 안에 무엇이 그려지는가"(보기 제공자)는 VS Code로 치면
Webview/Custom Editor가 하는 일과 성격이 비슷하다. 다만 확장으로 배포하는 구조가
아니라, 껍데기가 정한 자리에 보기 컴포넌트를 끼우는 방식이다.

## 6. 이 문서를 어떻게 쓰나

- 화면 요소를 부를 때 위 영문/한글 용어로 통일한다.
- "재검토 여지"로 표시된 항목(환영 뷰, 알림, 진행 표시, 컨텍스트
  메뉴 등)은 사용자가 기능을 알고 나서 넣을지 뺄지 판단할 후보다. 넣기로 하면 그
  결정과 근거는 스키마 문서(`DECISIONS` 등)로 올린다. 이 참조 메모에서 확정하지 않는다.
