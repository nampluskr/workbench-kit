# 반입할 것들의 라이선스

> 참조 메모 · 작성일: 2026-09-08
>
> 이 문서는 스키마 문서(`docs/`)가 아니라 `refs/`의 참조 자료다. 껍데기와 앱이 가져다
> 쓰기로 한 것들의 라이선스와, **배포할 때 무엇을 함께 넣어야 하는지**를 정리한다.
>
> 확인 방법을 함께 적는다. 이 프로젝트에서 라이선스를 잘못 적은 일이 두 번 있었으므로
> (D-3의 codicons를 MIT로 기재, 앞선 프로젝트의 "세 아이콘 테마" 서술), 출처 없이
> 옮겨 적지 않는다.

## 2. 주의할 두 가지

**아이콘 세트 셋이 각각 다르다.** 코드 라이브러리(dockview · monaco)는 전부 MIT라
"본문을 함께 넣으면 끝"이지만, 아이콘은 그렇지 않다.

| 세트 | 요구 |
| --- | --- |
| codicons | 저작자 표시 (CC BY 4.0) |
| seti | 본문 포함 (MIT) |
| vscode-icons | 저작자 표시 + 고쳐 쓰면 동일조건 공개 (CC BY-SA) |

저작자 표시가 둘이나 되므로, **화면이나 문서에 표시할 자리를 정해 두어야 한다.**
Help 메뉴의 정보(D-23)가 그 자리로 적당하다.

**vscode-icons는 확인했고, MIT가 아니었다.** 저장소의 `LICENSE`는 MIT이지만 그것은
**코드에 대한 것**이고, `README.md`가 아이콘을 따로 밝히고 있다 — 아이콘은
**CC BY-SA**이며 **브랜드 아이콘(회사·제품 로고)은 각자의 저작권 라이선스**를 따른다.

따라오는 것이 셋이다.

1. **저작자 표시가 필요하다.** codicons와 같은 요구다.
2. **CC BY-SA는 동일조건변경허락이다.** 아이콘을 **고쳐 쓰면** 그 결과물을 같은
   조건으로 공개해야 한다. 색이나 모양을 손대지 않고 그대로 쓰면 이 조건이 걸리지
   않는다. D-3이 "아이콘을 직접 그리거나 색 테마별로 따로 그리지 않는다"고 정했으므로
   지금 계획으로는 고칠 일이 없다. **다만 나중에 아이콘을 손보고 싶어지면 여기를
   먼저 본다.**
3. **브랜드 아이콘은 별개다.** 회사·제품 로고는 저작권과 별개로 상표 문제가 따라올
   수 있다. 이 껍데기는 복사해서 쓰는 템플릿이므로(INTENT 4절) 복사한 사람이 만드는
   앱에도 그대로 실린다.

부담스러우면 파일 아이콘 "컬러" 테마만 다른 세트로 바꾸면 된다. 세 테마는 서로
독립이라 "단순"과 "기본"에는 영향이 없다(D-17).

`CC BY-SA`의 판 번호(3.0 · 4.0 등)는 README에 적혀 있지 않다. 실제로 반입할 때
저장소의 아이콘 폴더에 별도 표기가 있는지 한 번 더 본다.

## 3. 앞선 프로젝트에서 빠져 있던 것

`tab-explorer-templates`는 seti와 vscode-icons의 아이콘 자산을 `shared/design/icons/`
아래에 넣어 쓰면서 **각 세트의 라이선스 본문을 함께 넣지 않았다.** MIT는 본문 포함을
요구하므로 이번에 가져올 때 채운다.

---

## 4. 배포할 때의 형태

`INTENT.md` 4절이 "설치형 라이브러리나 패키지로 배포하지 않는다. 복사해서 쓰는
템플릿으로 둔다"고 정했다. 즉 이 껍데기를 복사한 사람이 그대로 앱을 만들어 배포하게
되므로, **라이선스 파일이 템플릿 안에 처음부터 들어 있어야 한다.** 복사한 사람이
따로 챙길 것을 남기지 않는다.

한 폴더에 모아 두는 것을 권한다 — 예: `third-party/` 아래에 세트별 폴더와 라이선스
본문, 그리고 어느 것이 어디에 쓰이는지 적은 목록 하나.
