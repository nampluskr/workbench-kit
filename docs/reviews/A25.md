# A25 — workbench-kit 계획 외 D2Coding 번들 적대적 검증

- 구현자: Codex
- 검토 모델: Claude `opus-5.5`
- 대상: 번들 글꼴 로드, 에디터·터미널 글꼴 선택, 두 호스트 배포 대조, OFL 고지
- 기준: 시스템에 D2Coding을 설치하지 않고 두 호스트에서 번들 Regular·Bold 사용
- 필수 통과 Phase: 해당 없음 (계획 외 사용자 요청)

## 실행 회차

| 회차 | 소요 | 턴 | 결과 |
| --- | --- | --- | --- |
| 1/3 | 75초 | 14 | CLI에 `--max-turns` 옵션이 없어 지시한 3턴 상한을 넘었다. 지적은 참고하되 절차상 유효 검토로 세지 않는다. |
| 2/3 | 25초 | 3 | 글꼴 실패 경로 재검토. Critical·Major 0건, Minor 4건. |
| 3/3 | 71초 | 1 | 변경 소스 발췌를 제공한 읽기 전용 검토. Critical 0건, Major 1건(반박), Minor 3건. |

## 지적과 처리

| # | 심각도 | 재현 조건·지적 | 처리 |
| --- | --- | --- | --- |
| 1 | Major | 번들 TTF가 누락되거나 로드가 실패하면 시스템 폴백 글꼴로 앱이 시작된다. | 수정. Regular·Bold의 실제 로드 결과와 빈 배열을 확인한다. 실패·10초 시간 초과에는 앱 시작 대신 화면 오류를 표시한다. 2회차에서 Critical·Major 0건 확인. |
| 2 | Minor | `initWorkbench()` 오류를 글꼴 오류로 잘못 알릴 수 있다. | 수정. 앱 초기화는 글꼴 로드 `try/catch` 밖에서 실행한다. |
| 3 | Minor | 오류 때 `#app`이 없으면 메시지가 보이지 않는다. | 수정. `document.body`로 폴백한다. |
| 4 | Minor | 개발 서버의 인라인 CSS가 CSP에 막힐 수 있다. | 이번 요청은 `dist/` 배포판 대상이다. 배포판의 Electron·pywebview 양쪽에서 글꼴 로드를 실측했다. |
| 5 | Minor | 앱의 자동 시작을 거치지 않고 `TextEditorView`를 직접 만들면 사전 로드 보장이 없다. | 직접 생성은 진단용 노출이다. 일반 앱 진입은 사전 로드를 거치며 양쪽 호스트에서 확인했다. |
| 6 | Minor | 공식 1.3.3 파일인지 검토자가 확인할 수 없다. | GitHub 공식 릴리스 압축파일 해시와 추출한 두 TTF 해시를 확인했다. 배포 검사에 TTF 두 해시를 고정했다. |
| 7 | Minor | About의 `docs/refs/licenses.md` 안내가 배포물에서 유효하지 않다. | 수정. 배포물에 포함된 `licenses/`만 가리킨다. |

## 유효하지 않은 지적과 반박 근거

- 3회차의 Major: `FontFace.family`가 따옴표를 포함할 수 있어 호스트의 일치 판정이
  빈 배열이 된다는 주장. 현재 Electron·pywebview 실제 실행에서 각각
  `400`·`700` 두 얼굴이 `loaded`로 수집됐고 `verify:dist`는 정확히 두 얼굴과
  두 가중치를 단언한다. 빈 배열이면 통과하지 않는다.
- 3회차는 제공된 소스 발췌 밖의 파일이 Git에 추적되지 않을 수 있다고 적었지만,
  검토 범위 밖 추정이다. 로컬 빌드가 글꼴·라이선스를 배포물에 넣는 것은 확인했다.

## 미해결 · 남은 위험

- 시스템에 D2Coding이 설치되지 않은 별도 PC에서 수동 화면 검증은 하지 않았다.
  앱 전용 CSS 이름에 `local()`이 없고 양쪽 호스트에서 해당 번들 얼굴 로드가 확인돼
  시스템 설치 경로를 사용하지 않는다는 근거는 확보했다.
- 1회차 CLI의 3턴 상한 초과는 이번 기록에 남긴다. 2·3회차는 한도 안에서 끝났다.
