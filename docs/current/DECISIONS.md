# DECISIONS — workbench-kit v0.3

## D-1. 폴더 탭은 Activity Bar와 분리한 세로 레일로 둔다

**선택**

Activity Bar 바로 오른쪽, Explorer 바로 왼쪽에 `Folder Tabs` 전용 세로 레일을 둔다.
이 레일은 Tabby처럼 왼쪽에 세로로 배치한다. 폴더 아이콘과 폴더 이름을 항상 함께
표시하고, 전체 경로는 hover로 확인한다. 화면에 보이는 레일 헤더 제목은 `FOLDERS`다.
현재 활성 폴더 탭은 배경 또는 강조선으로 다른 탭과 구별한다. Activity Bar는 Explorer와
Folder Tabs 레일을 각각 보이게 하거나 감추는 전역 영역 제어를 계속 맡는다.

**근거**

Activity Bar는 어느 보기를 보일지 고르는 전역 제어 영역이다. 작업 폴더는 보기의
종류가 아니라 사용자가 유지하는 작업 대상이므로 같은 띠에 섞으면 역할이 흐려진다.
또한 30px 폭의 아이콘만으로는 이름이 같은 폴더나 여러 프로젝트를 구별할 수 없다.
이름을 읽을 수 있는 세로 탭은 Tabby의 측면 탭처럼 여러 작업 대상을 지속적으로
전환하는 감각을 주면서도 Explorer의 한 루트 모델을 유지한다. 활성 상태를 명확히
표시하면 사용자가 현재 Explorer가 어느 폴더에 연결됐는지 즉시 알 수 있다.

**배제한 대안**

- **Activity Bar에 폴더 아이콘을 동적으로 추가한다.** 전역 제어와 작업 대상이 섞이고,
  폴더 수가 늘면 식별과 세로 공간 관리가 어려워 배제한다.
- **가로 폴더 탭을 Explorer 위에 둔다.** Explorer 제목과 View Actions가 이미 있는
  좁은 영역을 더 압박하고, 사용자가 참고한 왼쪽 세로 탭 방식과도 맞지 않아 배제한다.

## D-2. Folder Tabs 레일은 독립적으로 감추고, 선택하면 Explorer를 다시 보인다

**선택**

Activity Bar 상단에 `Toggle Folder Tabs` 아이콘을 둔다. 아이콘은
`codicon-folder-library`를 사용하며, 기존 `Toggle Explorer` 다음에 배치한다. 이
아이콘과 `View` 메뉴의 `Show Folder Tabs` 항목은 Folder Tabs 레일만 보이게 하거나
감춘다. 별도 단축키는 두지 않는다.

Explorer와 Folder Tabs 레일은 독립된 표시 상태를 가진다. Explorer를 감춰도 Folder
Tabs 레일은 남는다. 이 상태에서 폴더 탭을 선택하면 선택한 폴더를 활성화하고 Explorer를
자동으로 다시 보인다. Folder Tabs 레일을 감춰도 폴더 탭 목록과 각 폴더의 Explorer
상태는 유지한다. 레일의 표시 상태는 현재 실행 중에만 유지하며, 앱을 다시 열면 기본
표시 상태로 시작한다. Zen Mode에서는 다른 창 껍데기 영역과 함께 레일도 감춘다.

**근거**

폴더 탭 레일을 감추고 에디터 폭을 넓히는 동안에도, Explorer가 감춰진 상태에서 작업
폴더를 빠르게 바꿀 수 있어야 한다. 두 영역을 독립시키면 사용자는 탐색기 트리와 작업
폴더 선택 목록을 필요한 만큼만 남길 수 있다. 폴더 탭을 눌렀는데 결과가 보이지 않는
상태는 혼란스러우므로, 선택 동작이 Explorer를 자동으로 다시 보이게 한다.

기존 Activity Bar의 영역 토글은 재시작 후 기본 표시 상태로 시작한다. Folder Tabs도
같은 수명 규칙을 따르면 폴더 목록 자체의 영구 저장 규칙과 표시 선호를 섞지 않는다.
`codicon-folder-library`는 단일 Explorer 토글의 파일 아이콘과 구별되면서, 여러 작업
폴더를 관리하는 레일의 의미를 나타낸다.

**배제한 대안**

- **Explorer를 감추면 Folder Tabs도 함께 감춘다.** 두 영역의 표시를 따로 조절하려는
  목적을 만족하지 못하므로 배제한다.
- **Explorer가 숨겨져 있을 때 폴더 탭을 눌러도 Explorer를 보이지 않는다.** 선택의
  결과가 화면에 나타나지 않아 사용자가 다시 Explorer 토글을 눌러야 하므로 배제한다.
- **Folder Tabs 표시 상태를 재시작 후에도 저장한다.** 기존 창 껍데기 토글과 수명
  규칙이 달라지고, 폴더 목록의 영구 상태와 표시 선호가 섞이므로 배제한다.
- **별도 단축키를 추가한다.** 현재 목적은 Activity Bar와 View 메뉴에서 명시적으로
  제어하는 것이며, 새 전역 단축키는 이번 버전에 필요하지 않아 배제한다.

## D-3. `Open Folder`는 새 폴더 탭을 추가하는 명령으로 바꾼다

**선택**

`Open Folder`와 최근 폴더 목록에서 선택한 경로는 현재 폴더를 교체하지 않고 항상 새
폴더 탭으로 추가한 뒤 활성화한다. 이미 등록된 정규화된 경로를 다시 선택해도 별도
탭을 만든다.

`Open Recent` 메뉴와 최근 폴더 목록은 그대로 남는다. 경로를 다시 찾는 수단이지 작업
폴더를 유지하는 수단이 아니므로, 폴더 탭이 그 역할을 대신하지 않는다. 다만 v0.2의
"마지막 폴더 하나를 다시 연다"(단일 폴더 복원)는 없앤다. 재시작 뒤 무엇을 여는지는
D-5의 폴더 탭 목록 복원이 정한다.

같은 정규화된 경로의 기본 표시 이름은 첫 탭에서는 폴더 이름 그대로이고, 두 번째부터는
`폴더 이름 (N)` 형식으로 구별한다. `N`은 같은 경로 탭의 기본 표시 이름에 아직 쓰이지
않은 2 이상의 가장 작은 정수다. 사용자가 정한 표시 별칭은 해당 탭에만 적용하며, 다른
탭의 `(N)` 번호를 바꾸지 않는다.

표시 별칭을 정한 탭은 기본 표시 이름을 쓰지 않으므로 그 탭이 갖고 있던 `(N)` 번호를
즉시 내놓는다. 풀린 번호는 같은 경로의 다음 탭이 위 규칙으로 다시 가져간다. 별칭을
빈 값으로 지우면 그 시점에 아직 쓰이지 않은 가장 작은 번호를 새로 받으며, 이 번호는
별칭을 정하기 전의 번호와 다를 수 있다.

**근거**

이번 버전의 목적은 작업 폴더를 남겨 두고 오가는 것이다. 현재 탭을 교체하는 동작을
유지하면 사용자가 작업 맥락을 잃고, 새 탭 추가와 교체의 차이를 매번 판단해야 한다.
같은 경로를 여러 탭으로 열면 서로 다른 펼침·선택·스크롤 위치를 각각 보존하며,
같은 폴더의 서로 다른 작업 맥락을 나란히 유지할 수 있다. `(N)` 접미사는 실제 경로를
바꾸지 않고 중복 탭을 화면에서 구별한다.

**배제한 대안**

- **현재 활성 폴더 탭을 교체한다.** 기존 작업 폴더가 목록에서 사라져 폴더 탭을 두는
  목적과 맞지 않아 배제한다.
- **`Add Folder`와 `Replace Current Folder`를 모두 제공한다.** 현재 사용 목적에는
  교체 경로가 필요하지 않고 명령만 늘어나므로 배제한다.
- **같은 경로를 선택하면 기존 탭을 활성화한다.** 같은 폴더의 서로 다른 Explorer
  상태와 작업 맥락을 동시에 유지할 수 없으므로 배제한다.
- **`Open Recent` 메뉴를 없애고 폴더 탭이 그 역할을 대신한다.** 탭을 닫은 폴더는
  경로를 처음부터 다시 찾아야 하므로 배제한다. 두 장치의 목적이 다르다.
- **별칭을 정한 탭이 자기 `(N)` 번호를 계속 붙잡는다.** 화면에 쓰이지 않는 번호가
  빈 자리로 예약돼 다음 탭이 더 큰 번호를 받게 되므로 배제한다. 별칭을 지웠을 때
  원래 번호로 정확히 돌아오는 이점보다, 보이지 않는 번호가 소비되는 혼란이 크다.

## D-4. 폴더 탭은 닫기·정렬·표시 별칭을 가진다

**선택**

`FOLDERS` 헤더에는 `Add Folder`, `Rename Folder Tab` 순서의 아이콘 두 개만 둔다.
`Add Folder`는 `Ctrl+O`와 같은 폴더 선택·탭 추가 동작을 한다. `Rename Folder Tab`은
현재 활성 탭의 표시 별칭을 바꾸며, 활성 탭이 없으면 비활성화한다.

폴더 탭은 클릭으로 활성화하며, 세로 드래그로 순서를 바꿀 수 있다. 드래그 중에는
삽입될 위치를 보여 준다. 각 탭은 hover 시 `×`를 보이고, 이 아이콘은 탭 등록만
제거하며 실제 경로·폴더·파일은 바꾸지 않는다.

활성 탭을 닫으면 레일에서 바로 아래 탭이, 아래가 없으면 바로 위 탭이 활성이 된다.
활성이 아닌 탭을 닫으면 활성 탭은 그대로 둔다. 마지막 탭까지 닫으면 활성 탭이 없고
Explorer는 폴더를 열기 전의 빈 상태로 돌아간다.

Rename 아이콘을 누르면 활성 탭의 인라인 입력 행이 열린다. `Enter`는 표시 별칭을
저장하고 `Escape`는 취소한다. 이 별칭은 실제 경로나 파일시스템 이름을 바꾸지 않는다.
같은 경로에서 자동으로 붙은 `(N)` 접미사는 기본 표시 이름을 구별하는 규칙이며, 표시
별칭을 정한 탭에는 적용하지 않는다. 탭이 많아져 세로 영역을 넘으면 폴더 탭 레일만
스크롤한다.

**근거**

등록한 작업 폴더는 사용자의 작업 순서와 이름으로 정리돼야 한다. Warp의 탭처럼
클릭·드래그·hover 닫기라는 직접 조작을 쓰면 별도 화면을 열지 않고도 전환·정렬·제거를
할 수 있다. 실제 경로의 마지막 이름만으로는 같은 이름의 프로젝트를 구별할 수 없으며,
테스트 목적이나 역할을 나타내는 별칭이 필요할 수 있다. 이 조작은 폴더 탭의 표시와
목록에만 영향을 주고 실제 파일시스템에는 영향을 주지 않는다.

**배제한 대안**

- **추가 순서와 실제 폴더명만 고정한다.** 작업 우선순위와 식별 방식을 사용자가
  조정할 수 없어 배제한다.
- **탭 이름 변경으로 실제 폴더 이름도 바꾼다.** 이 기능은 파일시스템 변경이 아니며,
  예상하지 못한 외부 변경을 만들므로 배제한다.
- **`F2`로 이름 변경을 시작한다.** 이 키는 껍데기가 앱 보기로 넘기는 키이므로 Folder
  Tabs 전용 동작으로 예약하지 않고, 헤더의 Rename 아이콘으로 한정한다.
- **Folder Tabs에 `…` 또는 우클릭 메뉴를 둔다.** 필요한 조작은 헤더의 Add·Rename과
  탭 hover `×`로 모두 제공하므로, 숨은 추가 메뉴를 만들지 않는다.
- **탭 수를 제한한다.** 임의의 한도는 작업 방식에 근거가 없고, 레일 스크롤로 해결할
  수 있으므로 배제한다.
- **활성 탭을 닫으면 직전에 활성이었던 탭(MRU)으로 간다.** 레일의 시각적 순서와
  활성이 옮겨 가는 자리가 어긋나 다음에 무엇이 열릴지 예측하기 어려우므로 배제한다.
- **활성 탭을 닫으면 아무 탭도 활성으로 두지 않는다.** 폴더를 하나 정리할 때마다
  Explorer가 비고 사용자가 다음 폴더를 다시 골라야 하므로 배제한다.

## D-5. Explorer 상태는 폴더 탭마다 저장하고 재시작 뒤에도 복원한다

**선택**

각 폴더 탭은 Explorer의 펼침 상태, 선택 항목, 스크롤 위치를 독립적으로 가진다.
등록 폴더 목록, 순서, 표시 별칭, 마지막 활성 탭과 함께 로컬 저장소에 저장하고 앱을
다시 열 때 복원한다.

**근거**

폴더 탭 전환의 가치는 이전에 보던 위치로 곧바로 돌아가는 데 있다. 루트만 다시 열면
사용자는 매번 같은 폴더를 펼치고 위치를 다시 찾아야 한다. Electron과 pywebview가
모두 지속 저장소를 사용하므로 두 호스트에서 같은 복원 규칙을 검증할 수 있다.

**배제한 대안**

- **탭을 누를 때마다 루트만 보이는 초기 트리로 시작한다.** 폴더 전환의 작업 맥락을
  보존하지 못하므로 배제한다.
- **펼침 상태만 복원한다.** 선택 위치와 스크롤 위치를 다시 찾아야 하므로 배제한다.
- **현재 실행 중에만 폴더 탭을 기억한다.** 앱을 다시 열면 작업 구성이 사라져 반복
  작업에 불리하므로 배제한다.

## D-6. 사라진 폴더는 탭을 유지한 오류 상태로 표시한다

**선택**

복원하거나 활성화하려는 폴더 경로가 삭제되었거나 이동되어 열 수 없으면 해당 폴더
탭을 자동으로 제거하지 않는다. 탭은 오류 상태와 경로 오류를 표시하고, 사용자는
새 경로를 선택해 연결을 바꾸거나 탭을 닫을 수 있다.

**근거**

경로가 잠시 접근할 수 없거나 사용자가 다른 위치로 이동한 경우에도 등록 탭 자체는
작업 의도를 담고 있다. 자동 제거는 사용자의 목록과 별칭을 되돌릴 수 없게 만든다.
사용자가 복구와 제거 중 어느 쪽을 할지 결정해야 한다.

**배제한 대안**

- **열 수 없는 탭을 자동 제거한다.** 일시적 접근 실패와 영구 삭제를 구별하지 못하고,
  사용자 설정을 잃게 하므로 배제한다.
- **앱 시작 시마다 제거 또는 새 경로 지정을 묻는다.** 여러 경로가 없을 때 시작 흐름을
  막고, 사용자가 나중에 조치할 선택권을 줄이므로 배제한다.

## D-7. 에디터 전환 방식은 `View` 메뉴의 전역 모드로 고른다

**선택**

`View` 메뉴에 서로 배타적인 라디오 항목 `Shared Editor`와 `Folder Workspace`를 둔다.
선택한 전역 모드는 모든 폴더 탭 전환에 적용한다.

- `Shared Editor`: 폴더 탭을 바꿔도 Explorer만 전환하고, 에디터 탭·활성 탭·분할
  레이아웃은 그대로 둔다.
- `Folder Workspace`: 폴더 탭마다 에디터 탭·활성 탭·분할 레이아웃을 따로 보존하고,
  폴더 탭을 바꿀 때 해당 작업공간을 함께 전환한다.

**근거**

한 에디터에서 여러 폴더의 파일을 비교하는 작업과, 폴더별로 독립된 작업 화면을 쓰는
작업이 모두 있다. 탭마다 모드를 다르게 두면 현재 에디터가 왜 바뀌었는지 예측하기
어려워진다. 전역 라디오 선택은 화면 전체의 전환 규칙을 항상 하나로 유지한다.

**배제한 대안**

- **Explorer만 전환하는 방식만 제공한다.** 폴더별 에디터 구성으로 작업하려는 사용
  방식을 지원하지 못하므로 배제한다.
- **폴더별 작업공간 방식만 제공한다.** 여러 폴더의 파일을 하나의 에디터 탭·분할
  구성에서 비교하는 방식을 막으므로 배제한다.
- **폴더 탭마다 모드를 따로 둔다.** 전환 결과가 탭마다 달라져 전역 화면 상태로서의
  에디터 수명이 불명확해지므로 배제한다.
- **탭을 누를 때마다 모드를 묻는다.** 반복 전환을 방해하고 선택 상태가 남지 않으므로
  배제한다.

---

## D-8. 에디터 상태는 모드 전환 중 보존하되, 폴더 작업공간은 실행 중에만 유지한다

**선택**

Shared Editor와 Folder Workspace 사이를 바꿀 때 현재 에디터 상태를 버리지 않는다.
현재 상태를 떠나는 모드에 저장하고, 들어가는 모드의 마지막 상태를 복원한다. 처음
Folder Workspace로 바꿀 때에는 현재 Shared Editor 상태를 활성 폴더의 초기
작업공간으로 사용한다.

Folder Workspace의 폴더별 에디터 탭·분할·활성 상태는 현재 앱 실행 중에만 유지한다.
앱을 다시 열면 폴더 탭과 Explorer 상태는 복원하지만, 에디터는 기본 빈 상태에서
시작한다.

**근거**

모드 선택은 작업 방식을 바꾸는 일이지 현재 열어 둔 내용을 버리는 명령이 아니다.
따라서 같은 실행 안에서는 어느 모드로 돌아가도 마지막 작업 상태가 있어야 한다.
반면 에디터 보기와 분할을 영구 복원하면 보기 종류별 직렬화, 파일 변경·삭제 처리,
복원 실패 처리까지 새 수명 모델이 필요해져 이번 버전의 폴더 전환 범위를 넘는다.

**배제한 대안**

- **모드 전환 때 항상 빈 에디터로 만든다.** 단순한 메뉴 선택으로 작업 내용을
  잃게 하므로 배제한다.
- **모드 전환 전에 현재 상태를 버릴지 확인한다.** 보존 가능한 상태를 불필요하게
  파기하는 흐름이므로 배제한다.
- **Folder Workspace 에디터 상태를 재시작 후에도 복원한다.** 저장과 복원 실패에 대한
  별도 수명 모델이 필요해 이번 버전에서는 배제한다.

## D-9. 작업 폴더 루트는 껍데기 인프라이며, 트리 행의 리소스 종류와 다른 층이다

**선택**

껍데기가 "작업 폴더 루트"라는 개념을 아는 것은 `INTENT.md` 3절의 "껍데기는 리소스
종류를 모른다"에 어긋나지 않는 것으로 본다. 두 층을 구분한다.

- **껍데기 인프라 층** — 트리가 무엇에 뿌리내리는가. 작업 폴더 루트를 고르고, 목록에
  남기고, 전환하고, 사라진 경로를 알린다. `Open Folder`·`Add Folder`·Folder Tabs
  레일·`codicon-folder-library`·경로 존재 확인이 여기 속한다.
- **갈아끼우는 자리** — 트리의 행 하나가 무엇인가. 행이 파일인지 폴더인지 세션인지,
  고르면 무엇이 열리는지는 여전히 껍데기 밖에서 정한다.

`.claude/rules/common-core.md`의 "파일·폴더·터미널·세션이라는 낱말로 분기한다"
금지는 두 번째 층에만 적용한다. 공통 코어가 트리 행의 종류로 분기하지 않는다는
규칙은 그대로다.

**근거**

이 구분은 v0.3이 만든 것이 아니라 v0.1부터 있던 것을 말로 옮긴 것이다. v0.1의
`Open Folder`(`Ctrl+O`)와 최근 폴더가 이미 껍데기 메뉴에 있고, Explorer 트리는 이미
폴더 하나에 뿌리내린다. INTENT 3절이 막으려는 것은 껍데기의 트리·탭 기계가 행의
종류를 아는 것이지, 트리가 어디에 뿌리내리는지를 껍데기가 정하는 일이 아니다.

INTENT 7절의 검증 앱이 이 구분을 요구한다. 파일 커맨더는 "칸 둘에 폴더를 나란히"
두고, 멀티터미널은 "고른 폴더 경로에서" 터미널을 연다. 두 앱 모두 작업 폴더를 여럿
유지하는 껍데기를 전제로 하며, 그 관리를 앱마다 다시 만들게 하면 껍데기를 한 벌로
두는 목적(INTENT 2절)이 무너진다.

말로 남기지 않으면 같은 물음이 버전마다 다시 올라오고, 그때마다 판단이 달라질 수
있다. 경계를 문서로 고정해 다음 버전이 이 선을 넘는지 아닌지 판정할 수 있게 한다.

**배제한 대안**

- **`INTENT.md` 3절을 고쳐 작업 폴더 루트를 명시적 예외로 적는다.** INTENT는 버전이
  바뀌어도 변하지 않는 것만 담고, 흔들리면 major 변경을 뜻한다. 이번 건은 원칙이
  바뀐 것이 아니라 원칙의 적용 범위를 읽어 낸 것이므로 배제한다.
- **아무것도 기록하지 않고 진행한다.** v0.2까지의 선례만으로 넘어가면 경계가 문서에
  없어 다음 버전에서 같은 물음이 다시 올라오므로 배제한다.
- **폴더 탭 관리를 갈아끼우는 자리로 내린다.** 앱마다 작업 폴더 관리를 다시 만들어야
  하고, 두 갈래와 여러 앱에서 같은 동작을 보장할 수 없으므로 배제한다.

## D-10. 메뉴는 Layout·Appearance로 묶고 폴더별 작업공간을 기본으로 한다

**선택**

`View` 메뉴는 `Layout`과 `Appearance` 두 하위 그룹만 노출한다. `Layout`에는
`Show Sidebar`·`Show Roots`·`Show Tree`, 두 분할 명령과 단일 체크 항목
`Workspace per Folder`를 둔다. `Show Sidebar`는 Activity Bar를 제외한 Roots+Tree
영역을 뜻하며, `Ctrl+B`와 같은 조합 감추기·복원 명령이다. `Appearance`에는 색·아이콘
테마와 Title Bar·Status Bar·Line Numbers·Zen Mode를 둔다.

D-7의 `Shared Editor`/`Folder Workspace` 라디오 두 행은 `Workspace per Folder` 하나로
대체한다. 이 항목은 매 실행 시작 시 체크가 기본이며, 해제했을 때만 모든 Roots가 하나의
에디터 레이아웃을 공유한다. D-8의 실행 중 상태 보존과 비영속 규칙은 그대로 유지한다.

`File`은 실제 동작에 맞춰 `Add Folder...`, `Close All Tabs in Group`을 사용하고,
`New Tab`을 노출한다. 분할 명령은 `View > Layout`으로 옮기며 사용자 명령이 아닌
`Preset Info`는 제거한다.

**근거**

공간 배치와 시각 설정을 분리하면 View의 평면 목록이 짧아지고 명령 위치를 예측할 수
있다. 모드는 서로 배타적인 두 이름보다 하나의 긍정형 설정이 현재 상태를 더 직접적으로
보여 준다. 폴더별 작업공간이 이 버전의 핵심이므로 이를 기본으로 삼는다.

## D-11. 파일·폴더 수준 1 열기 모드와 단축키 및 상태바 연동

**선택**

1. **수준 1(Level 1) 껍데기 구현 범위 고정**:
   - 실제 디스크 I/O나 파일 내용 읽기, 폴더 디렉터리 트리 목록 로드, 외부 자식 프로세스(`node-pty`, cmd/shell) 구동을 일절 포함하지 않는다.
   - 열린 탭 내부에 대상 식별자 및 열린 모드 텍스트(`// File preset view: ${targetId} [Mode: Editor]` / `[Mode: Viewer]`, `Folder preset view: ${targetId} [Mode: File List]` / `[Mode: cmd]` / `[Mode: Terminal]`)만 표시하고 모드 변경 시 해당 텍스트 및 에디터 편집 가능 여부(`readOnly`)를 전환한다.

2. **상태바 모드 표시 및 조작 정책**:
   - 탭 우측 상단 헤더 툴바(Header Bar)는 적용하지 않고 탭 스트립을 간결하게 유지한다.
   - 상태바 우측(`statusbar-right`)에 아이콘 없이 텍스트 전용 버튼(`#statusbar-mode-btn`)을 배치한다.
   - 현재 활성 탭의 모드만 단일 표시한다:
     - 파일 탭: `File: Editor` 또는 `File: Viewer` (클릭 시 토글).
     - 폴더 탭: `Folder: File List` / `Folder: cmd` / `Folder: Terminal` (클릭 시 순환).
   - 더미 표시 배제: 파일 탭일 때 폴더 모드 더미(`Folder: -`), 폴더 탭일 때 파일 모드 더미(`File: -`)는 일절 표시하지 않는다. 활성 탭이 없거나 일반 탭일 때는 버튼을 숨긴다(`display: none`).
   - 탭을 전환하거나 탭이 닫혀 활성 탭이 바뀔 때마다 상태바 모드 버튼이 즉시 해당 탭의 모드로 자동 갱신된다.
   - 기본 모드 설정은 `localStorage`(`workbench:default-file-mode`, `workbench:default-folder-mode`)를 통해 영속화된다.

3. **단축키 및 메뉴 정립**:
   - `Ctrl+N`: 새 빈 탭 열기 (`File: New Tab`).
   - `Ctrl+O`: 파일 열기 대화상자 (`File: Open File...`).
   - `Ctrl+K Ctrl+O`: 폴더 열기 대화상자 (`File: Open Folder...`).
   - `View > Tab Mode`: 현재 활성 탭의 모드를 상단 햄버거 메뉴에서도 확인 및 전환할 수 있는 서브메뉴를 제공한다. 활성 탭이 파일일 경우 `Editor` / `Viewer`, 폴더일 경우 `File List` / `cmd` / `Terminal` 라디오 체크 항목이 노출되며, 활성 탭이 없거나 일반 탭일 때는 `No Active Tab`(비활성화)으로 안내된다. 메뉴 선택과 상태바 버튼 조작은 상호 즉각 동기화된다.

4. **빈 탭 재활용 (Empty Tab Takeover)**:
   - 수정되지 않은 빈 탭(`Untitled`, `targetId == null && !isDirty`)이 활성 상태일 때 파일이나 폴더를 열면, 새 탭을 옆에 추가하지 않고 해당 빈 탭 자리를 재활용하여 덮어쓴다.

**근거**

- 상태바에 무의미한 더미 텍스트를 노출하지 않고 현재 작업 중인 탭의 대상 모드만 정갈하게 표시함으로써 시각적 피로도를 줄이고 상태를 즉시 파악할 수 있다.
- 모드 전환을 상태바 버튼 클릭으로 지원하여 불필요한 헤더 툴바 버튼 난립을 방지하고 에디터/뷰어 작업 영역을 온전히 확보한다.
- 빈 탭 상태에서 파일을 열 때 탭이 계속 늘어나는 현상을 방지하여 사용성을 개선한다.

## D-12. 파일 확장자 필터는 전역 설정이며 Activity Bar에서 연다

**선택**

1. **전역 설정 하나**: 확장자 필터는 색·아이콘 테마, 기본 파일 모드와 같은 층의 전역
   설정이다. Explorer 트리와 모든 폴더 file-list 탭이 같은 필터를 읽고, 탭마다 따로
   두지 않는다. `localStorage`(`workbench:file-filter`)에 저장해 재시작 뒤에도 유지한다.
2. **Include / Exclude**:
   - Include의 기본값은 전체(`*.*`)이고, 고르면 그 확장자의 파일만 보인다.
   - Exclude의 기본값은 없음이다. Include보다 우선한다.
   - 확장자가 없는 파일(`README`, `.env`)은 `(no extension)`으로 고른다.
   - 대소문자를 가리지 않는다.
3. **폴더는 걸러지지 않는다**: 폴더와 `..`는 항상 보인다. 필터는 파일에만 걸리고,
   폴더 안을 미리 읽지 않는다.
4. **즉시 적용**: 필터 창의 체크 목록(지금까지 읽은 폴더에서 본 확장자)과 직접
   입력(`md, *.ts; .py`)은 바뀌는 즉시 반영된다. Apply·Cancel은 없고 `Clear`로
   되돌린다. Include에서 마지막 확장자를 해제하면 스스로 전체로 돌아가, 모든 파일이
   조용히 사라지는 상태를 만들지 않는다.
5. **여는 자리 — Activity Bar (v0.2 D-3의 예외)**:
   - 필터 버튼을 트리 토글 아래에 둔다.
   - 필터가 없으면 `codicon-filter`, 걸려 있으면 `codicon-filter-filled`로 그려
     현재 상태를 한눈에 보인다.
   - 마우스를 올리면 조건을 글로 보여 준다.
   - 맨 위 제목줄 토글과 맨 아래 상태표시줄 토글의 자리는 그대로 둔다.
6. **메뉴**: `View > File Filter`에 `Edit Filter...`, `Clear Filter`(필터가 없으면
   비활성)와 현재 Include/Exclude를 보여 주는 비활성 행을 둔다.
7. **코어 경계**: 확장자를 아는 코드(판정, 저장, 입력 해석, 필터 창)는 공통 코어 밖
   (`src/providers/`, `src/presets/`)에 둔다. 코어에는 범용 장치만 더한다: Activity Bar
   항목의 라벨·요소 조회, View 하위 메뉴 항목.

**근거**

- 확장자 필터는 "지금 무엇을 보고 싶은가"라는 작업 전체의 관점이라, 테마처럼 한 번
  정하면 트리와 목록에 함께 걸리는 편이 예측하기 쉽다.
- 필터가 켜진 줄 모르고 파일이 "사라졌다"고 오해하는 것이 가장 큰 위험이다. 늘 보이는
  세로 띠에 켜짐/꺼짐이 다른 아이콘을 두면 이를 막는다. v0.2 D-3이 세로 띠를 영역
  토글로 한정한 이유(성격이 다른 명령이 섞이면 찾기 어렵다)는 유지하되, 이 버튼은 보이는
  내용을 바꾸는 표시이자 토글에 가까워 예외로 둔다.
- 폴더를 거르지 않으면 걸러진 상태에서도 트리를 끝까지 탐색할 수 있고, 큰 폴더를
  재귀로 읽는 비용이 없다.

**배제한 대안**

- 탭마다 다른 필터: 탭을 나란히 비교하는 데는 좋지만, 어떤 탭에 무엇이 걸렸는지
  기억해야 하고 트리와의 관계가 모호해진다.
- file-list 주소칸 옆이나 트리 헤더에 필터 버튼: 필터가 걸린 사실이 그 영역을
  감추면 함께 사라진다.
- 맞는 파일이 없는 폴더를 숨김: 폴더 안을 재귀로 읽어야 해서 느리다.

## D-13. 메뉴에 Edit 묶음을 두고, Save·다중 커서를 켠다

**선택**

1. **Edit 묶음**: 햄버거 메뉴를 `File · Edit · View · Help` 순서로 둔다. Edit의 행은
   VS Code Edit 메뉴 순서를 따른다.
   - `Undo`(`Ctrl+Z`), `Redo`(`Ctrl+Y`)
   - `Cut`(`Ctrl+X`), `Copy`(`Ctrl+C`), `Paste`(`Ctrl+V`)
   - `Find`(`Ctrl+F`), `Replace`(`Ctrl+H`)
   - `Toggle Line Comment`(`Ctrl+/`), `Toggle Block Comment`(`Shift+Alt+A`)
   - `Select All`(`Ctrl+A`), `Add Next Occurrence`(`Ctrl+D`),
     `Add Cursor Above`/`Below`(`Ctrl+Alt+Up`/`Down`)
2. **대상과 비활성**: 행은 활성 탭 안의 텍스트 보기에 작용한다. 텍스트 보기가 없는 탭
   (file-list, 터미널, 빈 탭)에서는 전부 비활성이다. 읽기 전용(Viewer)에서는 글을
   바꾸는 행(Undo·Redo·Cut·Paste·Replace·주석)이 비활성이고, 되돌릴 것이 없으면
   Undo/Redo도 비활성이다.
3. **키는 보기의 것**: 행은 단축키를 보여 주기만 하고, 키는 계속 monaco가 받는다.
   예약 키 목록(`docs/reserved-keys.md`)은 바뀌지 않는다.
4. **메뉴에 있는 기능만**: 메뉴 행이 부르는 monaco 기여(`comment`, `clipboard`,
   `multicursor`)만 더 불러온다. 줄 이동·복제·삭제 같은 메뉴 밖 에디터 단축키는
   넣지 않는다.
5. **File > Save (`Ctrl+S`)**: File 묶음에 `Save`를 둔다. 활성 탭이 변경된 상태일 때만
   활성이고, 기존 앱 저장 처리(닫기 확인 창의 `Save`와 같은 경로)를 부른다. `Ctrl+S`
   키는 셸이 가져가지 않고, 파일 프리셋이 자기 텍스트 보기에 등록한다(예약 키 §4).
6. **다중 커서 켜기 — v0.1 X-12(D-18) 중 다중 커서 항목을 뒤집는다**: 보조 커서를
   하나로 접던 코드를 없애고 `Ctrl+D`, `Ctrl+Alt+Up/Down`, `Alt+클릭`을 쓸 수 있게
   한다. 자동완성·언어 서비스·미니맵은 계속 끈다.
7. **코어 경계**: 코어(`menu.ts`, `texteditor.ts`)에는 범용 장치만 더한다. 최상위 행의
   비활성 제공자, 텍스트 보기의 편집 명령 실행과 가능 여부, 주어진 영역 안의 텍스트
   보기 찾기. 무엇을 저장하는지는 앱이 정한다.

**근거**

- VS Code에 익숙한 사용자가 편집 명령을 메뉴에서 찾고, 단축키를 메뉴에서 배울 수 있다.
- 지금까지 `Ctrl+S`가 아무 일도 하지 않아, 저장하려면 탭을 닫아야 했다.
- 텍스트 편집기로 쓰는 시간이 늘어 다중 커서의 이득이 커졌다(사용자 결정).

**배제한 대안**

- 메뉴 밖 에디터 단축키까지 전부 켜기: 번들이 커지고, 이번 요청 범위(메뉴 항목)를
  넘는다.
- 셸이 `Ctrl+S`를 전역으로 가져가기: 예약 키 §4("저장은 앱 몫")와 어긋나고, 저장할
  수 없는 탭에서도 키를 빼앗는다.
- `Ctrl+K Ctrl+C` 같은 VS Code 코드 단축키: `Ctrl+K`는 셸이 예약한 코드 시작 키다.

## D-14. 탐색기에서 파일·폴더를 실제로 만들고, `F2`로 이름을 바꾼다

**선택**

1. **만들기**: 탐색기 헤더의 New File / New Folder로 입력한 이름으로 실제 디스크에
   만든다.
   - 부모는 선택한 폴더(파일이면 그 파일의 폴더)이고, 없으면 루트다.
   - 새 파일은 빈 파일이며 트리에서 선택되고 Editor 모드로 열린다.
   - 새 폴더는 선택만 한다.
2. **이름 바꾸기**: 트리 행에 포커스가 있을 때 `F2`로 그 자리에서 이름을 바꾼다.
   - 파일은 확장자 앞까지, 폴더는 전체 이름이 먼저 선택된다.
   - `Enter`나 포커스 이동으로 확정하고, `Escape`로 취소한다.
   - 우클릭 메뉴 항목은 두지 않는다(사용자 결정).
3. **덮어쓰지 않는다**: 같은 이름이 이미 있으면 만들기와 이름 바꾸기 모두 실패한다.
   - 대소문자만 바꾸는 이름 바꾸기는 허용한다.
   - 실패하거나 이름이 Windows 규칙에 맞지 않으면 상태표시줄에 이유를 보인다.
   - 만들기는 입력한 이름 그대로 입력 행을 다시 연다.
4. **열린 탭은 새 경로를 따라간다**: 이름을 바꾼 파일이나 바꾼 폴더 안의 파일 탭,
   file-list 탭이 새 경로와 제목으로 바뀐다.
   - 편집 중인 내용, ●, 모드는 유지되고, 이후 저장은 새 경로로 간다.
   - 되돌리기 기록은 새로 시작한다.
   - 터미널 탭은 건드리지 않는다.
5. **루트는 바꾸지 않는다**: 트리 루트(= 폴더 탭 자체)에서 `F2`는 아무 일도 하지
   않는다. 폴더 탭 등록 경로와 최근 목록이 옛 경로를 가리키게 되기 때문이다.
6. **코어 경계**: 코어 트리는 입력 행 장치(`promptRename`, 새 항목 입력의
   `initialValue`)만 더한다. 이름 검사, 디스크 동작, 탭 따라가기, `F2` 연결은 앱 층
   (`src/presets/explorer-file-ops.ts`, `src/main.ts`)과 호스트가 맡는다. `F2`는 예약
   키가 아니다(예약 키 §4).

**근거**

- 헤더의 만들기 버튼이 있는데 실제로 만들어지지 않는 것은 사용자가 기대하는 동작과
  어긋난다.
- VS Code와 같은 동작(`F2`, 확장자 앞까지 선택, 새 파일 열기)이라 익숙하다.
- 덮어쓰기를 막으면 입력 실수로 데이터를 잃지 않는다.

**배제한 대안**

- 이름을 바꾼 파일의 탭 닫기: 편집 중인 내용을 저장하거나 버리도록 강요한다.
- 탭을 그대로 두기: 저장하면 옛 이름의 파일이 다시 생긴다.
- 코어 트리가 `F2`를 직접 처리: 예약 키 §4("이름 바꾸기는 앱 몫")와 어긋난다.

## D-15. 텍스트로 볼 수 있는 파일만 에디터 탭으로 연다

**선택**

1. **판별 — 확장자와 내용**:
   - 알려진 바이너리 확장자(실행·라이브러리, 압축, 그림, 소리·영상, 오피스 문서,
     데이터베이스·모델, 글꼴)는 내용을 읽지 않고 거부한다.
   - 그 밖의 파일은 호스트가 앞 64KB를 읽어 판단한다.
     - NUL 바이트가 있으면 바이너리다.
     - UTF-8로 읽히면 UTF-8 텍스트다. BOM은 떼고, 64KB 경계에서 잘린 글자는 허용한다.
     - 아니면 CP949로 읽히는지 본다.
     - 둘 다 아니면 바이너리다.
   - 확장자 없는 텍스트(`README`)와 스크립트(`.bat`, `.ps1`, `.sh`)는 열린다.
2. **거부 표시**: 탭을 열지 않고 상태표시줄에 `Cannot open '<name>' — binary file`을
   띄운다. 트리 선택은 그대로다.
3. **모든 열기 경로에 적용**: 트리 클릭·더블클릭·`Enter`·옆 칸 열기, 우클릭
   `Open as Viewer`/`Editor`, `File > Open File...`.
4. **CP949 텍스트**: CP949로 읽어 Viewer(읽기 전용)로만 연다. Editor 전환은 막고
   상태표시줄에 `CP949 file — read-only`를 띄운다. 탭 툴팁은
   `Viewer (read-only, CP949)`다.
5. **최신 요청만 반영**: 판별은 비동기다. 연달아 누르면 마지막 요청만 탭을 연다.
6. **코어 경계**: 판별은 앱 층(`src/presets/file-types.ts`, `main.ts`, 파일 프리셋)과
   호스트(`probeTextFile`, `readLegacyTextFile`)가 맡는다. 공통 코어는 바뀌지 않는다.

**근거**

- 바이너리를 열면 탭에 오류 문구만 보여 쓸모가 없고, 미리보기 탭을 밀어낸다.
- 확장자만으로는 확장자 없는 텍스트나 흔치 않은 확장자를 놓치고, 내용만으로는 텍스트
  모양의 바이너리 형식(예: 이름만 바꾼 이미지)을 가리지 못한다. 둘을 함께 쓴다.
- 한국어 윈도우의 엑셀 csv는 CP949라 내용을 볼 수 있어야 한다. 저장하면 UTF-8로 바뀌어
  다른 프로그램에서 깨질 수 있으므로 편집은 막는다.

**배제한 대안**

- 확장자 허용 목록만 쓰기: 목록에 없는 텍스트 파일을 열 수 없다.
- CP949 편집 허용(UTF-8로 저장): 원본 인코딩이 조용히 바뀐다.
- 거부 시 알림 없음: 왜 안 열리는지 알 수 없다.
