# PLAN — workbench-kit v0.3

## 읽는 법과 이 순서에 걸린 규칙

**`BRIEF ①` 같은 표기는 `BRIEF.md` 5절 완료 조건을 위에서부터 센 번호다.** 그 절에
번호가 적혀 있지 않으므로 이 문서가 세는 순서를 규약으로 삼는다 — 목록이 바뀌면 이
참조도 함께 고친다. 전체 14개다.

**Phase 순서는 의존 때문이다.** Phase 1이 폴더 탭이라는 대상 자체를 만들고, Phase 2가
그 위에 조작을 얹고, Phase 4가 각 탭에 상태를 매단다. 반대 순서는 성립하지 않는다.
Phase 3·5는 앞의 것들에 얹히지만 서로 독립적이다.

**모든 Phase의 완료 조건은 두 갈래(Electron · pywebview)에서 각각 판정한다.** Phase마다
반복해 적지 않는다. `BRIEF ⑭`의 전건 대조는 Phase 6이 맡는다.

**판정은 화면에서 한다.** 요소가 DOM에 있는지로 끝나는 판정을 쓰지 않는다 — 실측
크기·색·조상 가시성까지 본다(v0.1 UT-EDT-003 · `.claude/rules/dockview-css.md`).

## Phase 1 — Folder Tabs 레일과 폴더 추가

**목적** — 작업 폴더를 여럿 등록해 두는 대상 자체를 만든다. 이번 버전의 토대다.

**대응** — `BRIEF ①②④` · `D-1` · `D-3` · `D-9`

**완료 조건**
- Activity Bar 오른쪽·Explorer 왼쪽에 세로 레일이 있고, 헤더 제목이 `FOLDERS`다.
  헤더에는 `Add Folder` · `Rename Folder Tab` 순서의 아이콘 두 개만 있다.
- 서로 다른 폴더를 둘 이상 추가하면 각각 **폴더 아이콘과 이름을 가진 세로 탭**으로
  남고, 전체 경로는 hover로 확인된다. 탭을 누르면 Explorer가 정확히 그 폴더
  하나의 트리로 바뀐다.
- 현재 활성 폴더 탭이 배경 또는 강조선으로 나머지와 **보기만 해도 구분**된다. 세 색
  테마 모두에서 성립한다.
- `Open Folder`(`Ctrl+O`)와 `Add Folder`가 현재 폴더를 **교체하지 않고** 새 탭을
  추가한 뒤 활성화한다. 이미 등록된 경로를 다시 골라도 별도 탭이 생긴다.
- 같은 경로의 기본 표시 이름이 첫 탭은 폴더 이름 그대로, 다음부터 `폴더 이름 (N)`이며
  `N`이 **아직 쓰이지 않은 2 이상의 가장 작은 정수**다. 탭 하나를 닫으면 그 번호가
  다음 탭에 다시 쓰인다.
- `Open Recent` 메뉴가 그대로 남고, 거기서 고른 경로도 새 탭으로 추가된다.
  v0.2의 "마지막 폴더 하나를 다시 연다"는 **경로가 0개**다.

## Phase 2 — 탭 조작: 닫기 · 정렬 · 표시 별칭

**목적** — 등록한 폴더를 사용자의 순서와 이름으로 정리하게 한다.

**대응** — `BRIEF ③⑤⑥` · `D-4`

**완료 조건**
- 탭을 **세로 드래그로 정렬**할 수 있고, 드래그 중 놓일 위치가 화면에 보인다.
- 각 탭이 hover에서 `×`를 보이고, 누르면 **탭 등록만** 사라진다. 실제 경로·폴더·파일이
  바뀌지 않는다.
- 활성 탭을 닫으면 **바로 아래 탭**이, 아래가 없으면 **바로 위 탭**이 활성이 된다.
  활성이 아닌 탭을 닫으면 활성 탭이 그대로다. 마지막 탭까지 닫으면 활성 탭이 없고
  Explorer가 폴더를 열기 전의 빈 상태로 돌아간다.
- `Rename Folder Tab`이 활성 탭에 **인라인 입력 행**을 열고, `Enter`가 저장 ·
  `Escape`가 취소한다. 활성 탭이 없으면 이 아이콘이 비활성이다.
- 표시 별칭이 실제 경로나 파일시스템 이름을 바꾸지 않는다. 별칭을 정한 탭은 자기
  `(N)` 번호를 **즉시 내놓고**, 그 번호를 같은 경로의 다음 탭이 가져간다. 별칭을 빈
  값으로 지우면 그 시점의 가장 작은 빈 번호를 새로 받는다.
- 탭이 세로 영역을 넘으면 **레일만** 스크롤된다. 탭 수에 한도가 없다.
- `F2`가 Folder Tabs에 예약되지 않고 탭 안 보기로 그대로 넘어간다.

## Phase 3 — 레일 토글과 Explorer 연동

**목적** — Explorer와 Folder Tabs를 각각 따로 감추고, 선택의 결과가 늘 보이게 한다.

**대응** — `BRIEF ⑨` · `D-2`

**완료 조건**
- Activity Bar의 `Toggle Explorer` 다음 자리에 `codicon-folder-library` 아이콘이 있고,
  `View` 메뉴의 `Show Folder Tabs`와 **같은 상태를 본다.** 전용 단축키는 0개다.
- 두 영역의 표시 상태가 독립적이다 — Explorer를 감춰도 레일이 남고, 레일을 감춰도
  Explorer가 남는다.
- **Explorer를 감춘 상태에서 폴더 탭을 선택하면** 그 폴더가 활성이 되고 Explorer가
  자동으로 다시 보이며 그 폴더의 트리가 나타난다.
- 레일을 감췄다 다시 보여도 등록 폴더·탭 순서·별칭·활성 상태·각 폴더의 Explorer
  상태가 그대로다.
- 레일의 **표시 상태만은 저장되지 않는다** — 앱을 다시 열면 기본 표시 상태로 시작한다.
  기존 Activity Bar 영역 토글과 같은 수명이다.
- Zen Mode에서 다른 창 껍데기 영역과 함께 레일도 감춰진다.
- 기존 Activity Bar의 전역 영역 제어 동작이 바뀌지 않는다.

## Phase 4 — 폴더별 Explorer 상태 보존과 복원

**목적** — 폴더를 오가도, 앱을 다시 열어도 보던 자리로 돌아오게 한다.

**대응** — `BRIEF ⑦⑧` · `D-5`

**완료 조건**
- 각 폴더 탭이 Explorer의 **펼침 상태 · 선택 항목 · 스크롤 위치**를 독립적으로 갖는다.
  폴더를 바꿨다 돌아오면 셋이 모두 복원된다.
- **같은 경로로 연 탭들도 각각** 다른 펼침·선택·스크롤을 유지한다.
- 앱을 다시 열면 등록 폴더 · 순서 · 표시 별칭 · 마지막 활성 탭 · 각 탭의 Explorer
  상태가 복원된다.
- 두 갈래 모두에서 재시작 복원이 성립한다 — pywebview는 v0.2에서 고친 영속 프로필
  (`storage_path`)을 실제로 타는지 **폴더 열기 → 재시작 흐름 전체**로 확인한다.

## Phase 5 — 사라진 경로의 오류 상태

**목적** — 열 수 없게 된 폴더를 조용히 지우지 않고 사용자에게 넘긴다.

**대응** — `BRIEF ⑩` · `D-6`

**완료 조건**
- 복원하거나 활성화하려는 경로가 삭제·이동되어 열리지 않으면 그 탭이 **자동으로
  제거되지 않고** 오류 상태와 경로 오류가 화면에 보인다.
- 그 탭에서 **새 경로를 지정해 연결을 바꾸거나** 탭을 닫을 수 있다.
- 오류 탭이 있어도 나머지 탭과 앱 시작 흐름이 막히지 않는다.
- 껍데기가 경로를 확인하는 것 말고 파일·폴더를 만들거나 지우거나 옮기지 않는다
  (`D-9`의 두 층 구분 · `.claude/rules/common-core.md`).

## Phase 6 — 에디터 전환 모드와 두 갈래 전건 대조

**목적** — Explorer만 바꿀지 에디터까지 바꿀지를 사용자가 고르게 하고, 두 호스트가
같은 결과를 내는지 전건으로 맞춘다.

**대응** — `BRIEF ⑪⑫⑬⑭` · `D-7` · `D-8`

**완료 조건**
- `View` 메뉴에 서로 배타적인 라디오 항목 `Shared Editor` · `Folder Workspace`가 있고,
  고른 모드가 **모든 폴더 탭 전환에 전역으로** 적용된다.
- `Shared Editor`에서 폴더 탭을 바꿔도 에디터 탭 · 활성 탭 · 분할 레이아웃이 유지된다.
- `Folder Workspace`에서 폴더 탭마다 에디터 탭 · 활성 탭 · 분할 레이아웃이 따로
  보존되고, 탭을 바꿀 때 그 작업공간이 함께 전환된다.
- **모드를 바꿔도 현재 실행 중의 에디터 상태가 버려지지 않는다** — 떠나는 모드에
  저장하고 들어가는 모드의 마지막 상태를 복원한다. 처음 `Folder Workspace`로 바꿀
  때는 현재 `Shared Editor` 상태가 활성 폴더의 초기 작업공간이 된다.
- `Folder Workspace`의 에디터 상태가 **재시작 후에는 복원되지 않고** 빈 에디터로
  시작한다. 같은 실행에서 폴더 탭과 Explorer 상태는 복원된다(Phase 4와 충돌 없음).
- **Phase 1~6의 모든 완료 조건을 Electron과 pywebview에서 각각 다시 돌려 결과가
  같다.** 두 갈래가 갈라지는 항목이 0개다.
- v0.2까지의 기존 검사 스위트에 **이번 버전이 만든 새 실패가 0건**이다. 남아 있던
  기존 실패(금지 값 `8px`·`16px`, `FR-F11` 대비 미달 5건, Electron 환경 플레이크)는
  이번 범위 밖이며 `BRIEF` 4절이 하지 않을 것으로 적은 항목이다.

## 적대적 검증

절차는 `docs/ADVERSARIAL-REVIEW.md`에 있다. 여기에는 이 프로젝트에서만 정해지는 두
가지만 적는다.

**필수 통과 Phase — 1 · 4 · 6** (사람 결정, 2026-09-16 — "수명·영속성이 생기는 Phase"
기준).

미해결 Critical이 있으면 다음 Phase로 넘어가지 않는다. 이 셋인 이유는 **1**이 폴더 탭이라는
새 대상과 `Open Folder`의 의미 변경을 동시에 들여와 나머지가 전부 그 위에 얹히고,
**4**가 영속 저장이라 조용히 깨지면 사용자 데이터가 사라지며, **6**이 새 에디터 수명
모델이자 두 갈래 전건 대조이기 때문이다.

**Phase별 공격 초점**

| Phase | 검토자에게 무엇을 깨라고 하는가 |
| --- | --- |
| 1 | 폴더 탭이 사용자 동의 없이 추가·교체·소멸하는 경로, 같은 경로의 `(N)` 번호가 겹치거나 건너뛰는 조작 순서, `Open Folder`가 아직 기존 폴더를 교체하는 경로를 찾아라 |
| 2 | 활성이 엉뚱한 탭으로 가거나 아무 탭도 활성이 아닌 상태로 남는 닫기 순서, 별칭과 `(N)`이 서로를 덮어써 두 탭이 같은 이름이 되는 경로, `×`가 파일시스템에 닿는 경로를 찾아라 |
| 3 | 아이콘·메뉴·실제 표시 상태가 서로 다른 것을 보는 경로, 폴더 탭을 눌렀는데 결과가 화면에 안 나타나는 상태, 레일 표시 상태가 재시작 뒤 되살아나는 경로를 찾아라 |
| 4 | 폴더를 오갈 때 상태가 다른 탭으로 새거나 덮어써지는 경로, 같은 경로 탭들이 상태를 공유해 버리는 경우, 재시작 복원이 한쪽 갈래에서만 되는 조건을 찾아라 |
| 5 | 오류 탭이 조용히 사라지거나 시작 흐름을 막는 경로, 경로 확인이 파일·폴더를 바꾸는 경로, 오류 상태에서 나머지 탭 조작이 막히는 조건을 찾아라 |
| 6 | 모드를 오갈 때 에디터 내용이 버려지는 경로, 두 모드의 상태가 서로 섞이는 경우, 폴더 워크스페이스가 재시작 뒤 되살아나는 경로, 두 갈래의 결과가 갈라지는 항목을 찾아라 |

이번 버전은 **기존 동작을 뒤집는 변경이 하나 있다** — `Open Folder`가 교체에서 추가로
바뀐다(`D-3`). 여기서만 회귀와 의도된 변경의 경계가 쟁점이 되므로, 검토자에게
`D-3`과 `BRIEF` 4절(하지 않을 것)을 함께 준다.
