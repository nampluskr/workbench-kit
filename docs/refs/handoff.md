# 구현 세션에 줄 지시문

> 참조 메모 · 작성일: 2026-09-08 · 대상 버전 v0.1
>
> 기획 세션에서 구현 세션으로 넘기는 자리다. **한 번에 하나씩** 준다.
> 기획 단계의 지시문은 `next-session-prompts.md`에 있고 그것은 다 끝났다.

## 넘기기 전에 알아 둘 것

- **`CLAUDE.md`가 매 세션 자동 로드된다.** 그래서 아래 지시문에 "INTENT를 고치지
  마라" 같은 것을 반복해 적지 않는다. 적혀 있는 것은 그 세션에서만 필요한 것이다.
- **전체 문서를 미리 읽히지 않는다.** `SPEC.md`는 133건이고 `DECISIONS.md`는 결정
  32개다. Phase가 쓰는 요구 ID와 결정만 열게 한다.
- **Phase를 건너뛰어 주지 않는다.** "전 Phase 다 해줘"는 주지 않는다.
- 필수 통과 Phase는 **1 · 4 · 5 · 7**이다. 그 넷은 미해결 Critical이 있으면 다음으로
  넘어가지 않는다.

## 2. 적대적 검증 (필수 통과 Phase 1 · 4 · 5 · 7 뒤에)

```
Phase <n>의 세션 내 리뷰어 검토가 끝났으니 반대 벤더 적대적 검증을 돌린다.

docs/ADVERSARIAL-REVIEW.md 를 읽고 그대로 따라.
공격 초점은 docs/current/PLAN.md "적대적 검증" 절의 Phase <n> 행이다.

- 검토자에게 구현 세션 대화·판단 근거·git 상태를 주지 마
- 제품 소스 파일과 공격 초점, 관련 PLAN 조항만 준다
- 실행은 3회까지. 소진하면 멈추고 보고해
- 반대 벤더 CLI를 못 쓰면 기본 모델로 폴백하지 말고 멈추고 보고해
- 결과를 docs/reviews/A<n>.md 에 6절 양식으로 남겨

미해결 Critical이 있으면 다음 Phase로 넘어가지 마.
```

## 쓰지 말 것

- **"전 Phase 다 진행해줘"** — 한 Phase씩 준다. 검증 게이트가 무력화된다.
- **"완료 조건은 네가 판단해"** — `PLAN.md`·`backlog.json`에 적힌 것으로만 판정한다.
- **"SPEC이 좀 이상하니 고쳐줘"** — 요구는 사람 것이다. 어긋남을 발견하면 보고하게
  하고, 고칠지는 사람이 정한다.
- **"검토는 세션 안 리뷰어로 충분해"** — 반대 벤더 검증을 대신하지 않는다
  (`ADVERSARIAL-REVIEW.md` 2절).
