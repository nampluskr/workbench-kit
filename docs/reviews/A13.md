## 2. 1회차 지적과 처리

### R1-1 (Critical) — 최소 폭 170px에서 `EXPLORER` 제목이 잘린다

- **지적**: 최소 폭 170px에서 헤더 여백 30px + 액션 넷 97px를 빼면 제목 자리가 ~43px뿐이라
  `EXPLORER`(~65px)가 `.sidebar-title`의 `text-overflow: ellipsis`로 잘린다. `FR-X6`(제목과
  네 액션이 잘리지 않는다) 위반.
- **처리**: **수정했다.** 최소 폭을 220px로 올리고(`setupSidebarResize` MIN + `.workbench-sidebar`
  `min-width`), 헤더 여백을 `0 10px`로 줄였다. `.sidebar-title`을 `flex: 0 0 auto; white-space:
  nowrap`로 바꾸고 `overflow: hidden`/생략 부호를 **없앴다** — 폭이 모자라면 조용히 잘리는
  대신 눈에 띄게 넘치므로 회귀가 검사에 잡힌다. `.sidebar-actions`도 `flex: 0 0 auto`.
- **검증**: `V2P5-FR-X6`가 `headerTitle.scrollWidth <= 실측 폭`(전체 텍스트가 그려짐) ·
  `header.scrollWidth <= clientWidth`(헤더 넘침 0) · 네 액션이 사이드바 안에 있음을 본다.

### R1-2 (Major) — 폭 조절에 키보드 경로가 없다 (NFR-8)

- **처리**: **수정했다.** 손잡이에 `tabindex="0"`을 주고 keydown 처리기를 더했다 —
  `ArrowLeft`/`ArrowRight`가 16px씩, `Home`이 최소, `End`가 창 폭의 40%. `reserved-keys.md`에
  3b절로 기록.
- **검증**: `V2P5-FR-X5-KEYBOARD`(손잡이 포커스 가능 · 화살표 · `Home`으로 폭이 바뀜).

### R1-3 (Major) — 끊긴 포인터 드래그가 계속 활성으로 남는다

- **처리**: **수정했다.** `pointerdown`에서 `setPointerCapture`, 정리는 `pointerup` ·
  `pointercancel` · 창 `blur` 모두에서. `stop()`은 멱등(`if (!dragging) return`)이고
  `releasePointerCapture`를 부른다.

### R1-4 (Major) — `FR-X4`의 "껍데기 생성 0" 단언이 죽어 있고, New Folder를 `Enter`로 확정하지 않는다

- **처리**: **수정했다.** `V2P5-FR-X4`가 `shellCreatedRows === 0`을 조건에 넣고, `tree`의
  데이터 공급자로 **폴더를 직접 읽어** 전후 `diskUnchanged`를 확인한다. New File(공백 포함
  이름 → `leaf`)과 New Folder(→ `container`) **둘 다 `Enter`로 확정**하고, `Escape`도 확인한다.

### R1-5 (Major) — `FR-X7`이 재실행을 안 하고, `FR-X5`가 `pointerup` 뒤만 잰다

- **처리**: **수정했다.** `V2P5-FR-X5`가 `pointermove`마다 폭을 재서 서로 다른 중간 폭 3개
  이상 · 단조 증가 · 편집 영역이 정확히 그만큼 줄어듦을 본다. `V2P5-FR-X7`이 모든 드래그
  전에 `localStorage`(키와 전체 내용)를 찍어 두고 아무것도 안 바뀐 것을 확인한다(런타임 변수
  제거 = 초기값 확인은 유지).

## 3. 2회차 지적과 처리

### R2-1 (Major) — `FR-X7`이 여전히 진짜 재실행을 안 한다 (SPEC divergence X-5)

- **지적**: 스위트가 `--sidebar-width`를 지우는 것으로 재실행을 흉내낼 뿐, Electron 러너는 창을
  한 번만 만들고 스위트 뒤 파괴한다. X-5는 Electron 쪽 **실제 재시작**을 요구한다.
- **처리**: **수정했다.** `v02-phase5-electron-runner.cjs`가 스위트 뒤에 실제 핸들러 경로로
  탐색기를 넓히고(`End` 키 → 창 폭 40%), `win.webContents.reload()` 후 `did-finish-load`를
  기다렸다가, 탐색기가 초기 ~240px로 돌아왔고 `--sidebar-width` 인라인이 없으며 재실행 전
  폭이 240에서 30px 이상 벗어나 있었음을 확인한다. 같은 userData 프로필이라 localStorage는
  reload를 건너 살아남으므로, 어디든 폭을 저장했다면 잡힌다. X-5대로 Electron만.
- **검증(실행 확인)**: 러너에서 506px로 넓힌 뒤 reload → 240px. `[PASS]`.

### R2-2 (Major) — 앱 액션이 많으면 최소 폭 보장을 무너뜨린다

- **지적**: 220px는 앱 액션 하나를 가정하는데 `addSidebarViewAction`은 개수 제한이 없다.
  `.sidebar-title`과 `.sidebar-actions`가 둘 다 안 줄어들어서 앱 액션이 충분히 많으면 액션
  묶음이 탐색기 밖으로 밀린다.
- **처리**: **수정했다.** `.sidebar-app-actions`를 `flex: 0 1 auto; min-width: 0; overflow: hidden`
  으로 — 헤더가 좁으면 앱 액션 묶음이 **먼저** 자리를 내주고 자기 내용을 자른다. 껍데기 네
  액션(`#sidebar-action-*`에 명시적 `flex: 0 0 auto`)과 `EXPLORER` 제목은 절대 안 줄어든다.
- **검증**: `V2P5-FR-X6`가 최소 폭으로 끌기 전에 **앱 액션 넷**을 더 등록하고, 제목(전체 텍스트가
  그려지고 사이드바 안) · 껍데기 액션 넷이 모두 탐색기 안에 있음을 본다.

## 4. 3회차 지적과 처리

### R3-1 (Major) — reload는 앱 재시작이 아니다

- **지적**: 러너가 같은 `BrowserWindow` · 같은 프로세스에서 `webContents.reload()`만 한다. `BRIEF`
  · `SPEC` divergence X-5가 요구하는 "실제 재시작"이 아니다. Electron 메인 프로세스가 폭을
  저장하고 새 창을 만들 때만 적용하는 변형이라면 이 검사를 통과한다.
- **처리**: **수정했다.** `createWindow()`를 함수로 빼고, 스위트 뒤에 폭을 실제 핸들러로 바꾼 뒤
  (`End` 키 → 창 폭 40%) **새 `BrowserWindow`를 만들어** 그 창을 확인한다(옛 창은 그 뒤 파괴).
  `window-all-closed`에 빈 핸들러를 둬 창 교체 중 앱이 안 꺼지게 했다. 같은 userData 프로필이라
  localStorage · 메인 프로세스 상태는 살아남고 CSS 변수 · DOM은 새로 시작한다.
- **검증(실행 확인)**: 러너에서 506px로 바꾼 뒤 새 창 → 280px, `--sidebar-width` 인라인 없음. `[PASS]`.
- **참고**: 껍데기 · 두 갈래 호스트 어디에도 사이드바 폭을 저장하는 코드가 0줄임을 grep으로
  확인했다(localStorage엔 `last-folder` · `recent-folders`뿐).

### R3-2 (Major) — 잘린 앱 액션 버튼이 안 보이는데 포커스는 받는다

- **지적**: 최소 폭에서 `.sidebar-app-actions`가 `overflow: hidden`으로 잘리는데, 잘려 안 보이는
  네이티브 버튼이 여전히 `Tab` 순서에 남아 `Enter`로 안 보이는 명령을 부를 수 있다.
- **처리**: **수정했다.** 최소 폭을 260px로 올리고(제목 + 껍데기 넷 + 앱 액션 여유), 기본 폭을
  280px로. `ExplorerTitlebarController`가 렌더 뒤 · `ResizeObserver`로, **박스 밖으로 잘린 앱 액션
  버튼에 `tabindex="-1"` · `aria-hidden="true"`**를 준다. 보이는 버튼은 `tabindex="0"`.
- **검증**: `V2P5-FR-X6`가 앱 액션 **열 개**를 등록해 최소 폭으로 끈 뒤, 잘린 버튼(7개)이 전부
  탭 순서 밖 · 보이는 버튼은 탭 가능임을 확인한다.

### R3-3 (Major) — 새 뷰 액션이 마우스 없는 경로 목록에 없다

- **지적**: `NFR-8`은 1절의 모든 명령에 문서화된 키보드 경로를 요구하는데 `reserved-keys.md`
  5절이 메뉴 · 세로 띠 · 탭 줄만 적고 New File · New Folder · Refresh · Collapse All을 빠뜨렸다.
  절 제목도 옛 `NFR-7`로 남아 있다.
- **처리**: **수정했다.** 5절에 탐색기 뷰 액션 행과 폭 조절 행을 더하고 제목을 `NFR-8`로.

### R3-4 (Minor) — PROGRESS 기록이 2회차 상태와 어긋난다

- **처리**: **수정했다.** `WK-071` 항목의 "최소 170px" · "진짜 재실행 확인은 사용자 몫"을 실제
  값(clamp) · 자동화된 재시작 확인으로 고쳤다.
