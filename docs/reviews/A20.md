## 유효하지 않은 지적과 반박 근거

**지적 3의 앞부분(비활성 복원 탭은 재시작 시 경로를 검사하지 않는다)** — 이 프로젝트의
기존 지연 로딩 철학과 일치한다고 보아 버그로 처리하지 않았다:

- PLAN.md Phase 4의 재시작 복원(D-5)도 **활성 탭 하나만** 실제로 폴더를 연다 — 나머지
  탭은 등록만 되고 클릭해야 로드된다. Phase 5의 "복원하려는 경로"도 같은 의미로 읽는
  것이 일관적이다.
- 등록된 모든 탭의 경로를 시작 시점에 전부 검사하면 탭이 많을 때 시작이 느려지고,
  "껍데기는 경로 확인만 한다"는 원칙과는 별개로 이번 버전 범위 밖의 성능/UX 결정이
  새로 필요해진다. `backlog.json`에 그런 task가 없다.
- 실제 버그는 "복원 시 검사를 안 한다"가 아니라 "복원 시 **이전 오류를 지우지 않는다**"
  쪽이었고(지적 3의 뒷부분), 그것만 고쳤다.

## 미해결 · 남은 위험

- 비활성 복원 탭의 경로 유효성은 여전히 클릭 시점에만 확인된다 — 위 반박 근거에서 밝힌
  의도된 설계다. 필요하다고 판단되면 새 backlog task로 다뤄야 한다.
- 재시작 전 오류 → 재시작 후 정상 시나리오는 `restoreTabs()` 단위 테스트
  (`V5P5-RESTORE-CLEARS-STALE-ERROR`)로만 확인했고, Phase 4처럼 실제 2-프로세스
  재시작으로 끝까지 확인하지는 않았다 — Phase 5는 필수 통과가 아니라 그 정도까지는
  하지 않았다.
