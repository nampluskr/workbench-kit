# A26 — workbench-kit F3/F4 보기·편집 단축키 적대적 검증

- 구현자: Codex
- 세션 내 리뷰어: 메뉴가 열린 상태에서 뒤쪽 화면에 F3/F4가 적용되는 문제 발견; 수정 확인
- 반대 벤더: Claude `opus-5.5`
- 대상: `src/main.ts`, `src/core/tree.ts`
- 기준: 탐색기 `Ctrl+F` 검색·`F3/F4` 파일 열기, 현재 파일 탭 `F3/F4` 모드 설정, 상태바 동기화, 다른 탭의 키 보존
- 필수 통과 Phase: 해당 없음 (계획 외 사용자 요청)

## 유효하지 않은 지적과 반박 근거

- 기존 F2가 메뉴 뒤에서 동작할 수 있다는 지적은 이번에 추가한 F3/F4 동작과 무관하다. 기존 F2의 처리 범위는 변경하지 않았다.
- 검색 입력창 안에서 다시 `Ctrl+F`를 누르는 경우와 탐색기 빈 상태의 `Ctrl+F`는 이번 요구의 트리 목록 단축키 범위 밖이다.
- `Shift+F10`으로 탐색기 우클릭 메뉴를 열 수 없다는 지적은 이번 단축키 변경 이전의 동작이다.
- 3회차가 제시한 `e.code` 불일치 가능성은 트리 검색과 메뉴 차단 처리 모두 `e.key`를 사용하므로 성립하지 않는다.

## 미해결 · 남은 위험

- Electron 실행 검증은 실제 요소에 포커스를 준 뒤 합성 키 이벤트를 보낸다. 분할 그룹에서 운영체제의 물리 키 입력까지 확인한 수동 검증은 수행하지 않았다.
- 전체 레거시 회귀 스위트는 누락된 `docs/current/SPEC.md` 등 기존 검사 전제 때문에 통과하지 않는다. 이 과제의 Electron 동작·CP949 제한 검증, TypeScript 검사, 빌드는 통과했다.
