## 1. 방침 요약 (DECISIONS D-1 · D-2)

- **최소 구현이 원칙이다.** 무빌드가 원칙이 아니다. 필요한 기능만 구현한다.
- **빌드를 전제로 한다.** 코드가 바뀌면 무조건 재빌드한다.
- **VS Code OSS는 fork하지 않는다.** 전체를 가져와 줄이는 top-down이 아니라, 필요한
  기능만 밑에서부터 구현하는 bottom-up이다.
- **빌드해서 쓰는 라이브러리는 쓴다.** monaco-editor · codicons 등.

## 2. 확보 수단 두 가지

요소를 이 껍데기에 넣는 방법은 둘 중 하나다.

| 수단 | 뜻 | 예 |
| --- | --- | --- |
| **참조 재구현** | VS Code OSS의 동작·구현을 참고해 필요한 만큼만 새로 짠다 | 탭 이동·분할 규칙·선택/포커스·키보드 |
| **라이브러리 반입** | 독립 배포된 라이브러리를 빌드에 넣어 그대로 쓴다 | codicons(아이콘), monaco-editor(코드/텍스트 보기) |

fork 후 축소(top-down)와 무빌드 반입은 D-1·D-2에서 배제됐다.

## 4. 다음 할 일

- **정해짐**: 아이콘은 라이브러리로 간다(D-3). 터미널 등 살아 있는 보기는 앱 요소이고
  껍데기는 탭·수명·호스트 브릿지만 제공한다(D-4). 탭은 사용자가 추가할 때만 늘어나며
  탐색기 선택은 현재 탭에서 연다(D-5) — 미리보기/고정 탭은 이로써 두지 않는다.
- **재검토(미정) 항목**이 지금 사람이 정할 대상이다: Welcome View, 코드/텍스트 보기
  (monaco 채택 여부와 범위), 컨텍스트 메뉴, 알림/진행 표시.
- 각 항목을 정하면 그 결정과 근거·배제한 대안을 `DECISIONS.md`로 올린다. 이 참조
  메모에서 확정하지 않는다.
- monaco-editor를 채택하면 "최소 구현" 관점에서 어느 기능까지 켤지(읽기 전용·문법
  강조만 등)를 함께 정한다.
