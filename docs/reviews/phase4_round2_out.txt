### Major ? Phase 4 is verified only under Electron

**Exact Reproduction Condition**

Run:

```powershell
npm run verify:phase4
```

The verifier launches only `npx.cmd electron` at [verify-phase4.mjs](/D:/projects/workbench-kit/scripts/verify-phase4.mjs:88), and the runtime runner imports only Electron at [phase4-electron-runner.cjs](/D:/projects/workbench-kit/scripts/phase4-electron-runner.cjs:1).

There is no pywebview runner executing the Phase 4 assertions. The pywebview smoke test used elsewhere does not exercise tab switching, dragging, renderer modes, lifecycle, closing, splitting, or opening rules.

**Violated Clause / Specification ID**

- SPEC common judgment rule: every FR must be evaluated independently under Electron and pywebview.
- PLAN Phase 4 completion: all 37 associated requirements must produce their specified result.
- FR-H1, as incorporated by the SPEC common judgment rule.
- PLAN Phase 4 adversarial focus: actual lifecycle behavior, especially around movement, closing, and pane boundaries.

**Why This Prevents Phase 4 Completion**

Passing the same built assets to two hosts is not equivalent to executing the required interactions in both hosts. Input dispatch, focus, keyboard handling, drag behavior, resizing, and window-boundary behavior can differ between Electron and pywebview.

Consequently, the current verifier proves at most the Electron branch and cannot satisfy the explicit two-branch completion rule.

**Recommended Fix**

Extract the browser assertions into a host-neutral test module and run it through:

- the existing Electron runner; and
- a pywebview runner that loads the same `dist` artifact and returns structured assertion results.

Compare the complete result set and require zero missing, failed, or divergent assertion IDs.

### Minor ? Closed renderers remain strongly retained indefinitely

**Exact Reproduction Condition**

```javascript
const panel = editor.addNewTab();
const id = panel.id;
editor.closePanel(panel);

editor.getContentRenderer(id) !== undefined; // true
```

`createComponent` inserts each renderer into `contentRenderers` at [editor.ts](/D:/projects/workbench-kit/src/core/editor.ts:220). The wrapped `dispose` increments statistics and delegates disposal, but never removes the renderer from that map at [editor.ts](/D:/projects/workbench-kit/src/core/editor.ts:222).

Repeating open/close operations causes the map to retain every disposed view, including its detached DOM tree and application-owned fields.

**Violated Clause / Specification ID**

- FR-E3.
- D-24 lifecycle intent.

The disposal callback is invoked, so the explicit disposal count requirement passes, but the shell continues owning the supposedly closed instance.

**Recommended Fix**

Delete the renderer from `contentRenderers` inside the wrapped disposal function, preferably in `finally`. Keep only the small aggregate record in `panelLifecycleStats`.
