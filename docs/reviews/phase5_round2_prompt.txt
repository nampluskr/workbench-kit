2. Major (menu.setAction() lets app code override/hijack shell-owned commands, e.g.
   file:open-folder, view:zen-mode, help:about, and reach View/Help despite no
   addAppViewItem/addAppHelpItem method):
   - `window.__workbenchAppSurface` does not expose `menu` at all — only
     `addFileMenuItem`, which appends a caller-supplied item (id + its own action)
     below the separator and cannot touch existing ids. Verified by
     P5-FR-I8-SURFACE-NO-MENU-CONTROL above.

3. Major (KindDispatchRenderer.update() disposes and recreates the view on ANY params
   change, including unrelated metadata like isDirty, destroying a live view D-4 says

   - kind-registry.ts's `update()` now compares merged `kind`/`targetId` against the
     previous values and only calls `renderForCurrentParams()` (dispose + recreate)
     when one of them actually changed. Unrelated metadata updates leave the live
     inner view untouched.

     `.tree-row.focused[data-id]`), and dispatches a real `Enter` keydown to open each

6. Major (the core-purity verifier in verify-phase5.mjs checked only 6 hand-picked
