## 유효하지 않은 지적과 반박 근거

**#8 (2회차 Major, `npm test`가 phase6-suite.js 단계에서 통과 불가)** — 보류, 근거:

- `PLAN.md`의 "적대적 검증" 절이 명시적으로 이번 버전의 **유일한 기존 동작 반전**(`Open
  Folder`가 교체 → 추가, D-3)을 "회귀와 의도된 변경의 경계가 쟁점"이라 부르며, 그 대조를
  **Phase 6의 검토자에게** `D-3`과 `BRIEF` 4절을 함께 주도록 지정한다 — Phase 1이 아니다.
- Phase 1 자체의 완료 조건은 "v0.2의 마지막 폴더 하나 복원 경로가 0개"이며, 이는
  `V3P1-RESTORE-IS-NOOP`·`V3P1-NO-LAST-FOLDER-KEY` 두 검증으로 이미 실측 확인됐다 —
  "그 경로가 실제로 더는 동작하지 않는다"는 사실과 "낡은 v0.2 스위트의 문구가 그 사실과
  다시 어긋난다"는 사실은 다른 문제다.
- `npm test`는 Phase 1 이전부터 이미 초록이 아니었다 — `src/style.css`의 금지 값
  `8px`(3건)·`16px`(1건)이 `verify:phase2` 단계에서 이미 실패하며, `&&`로 묶인 `npm test`는
  그 단계에서 멈춘다. 즉 이번 변경 이전에도 `npm test` 한 번으로 phase6 단계까지 도달하지
  않았다 — 이번 변경이 "통과하던 명령을 처음으로 깨는" 것이 아니다.
- `backlog.json`의 WK-110("두 갈래 전건 대조와 회귀 0건 확인")이 정확히 이 정리를 맡은
  Phase 6 필수 통과 task다. Phase 1에서 `phase6-suite.js`를 고치면 Phase 6의 범위를
  선점하고, Phase 2~5가 만들 추가 변경(닫기 UI 등)을 반영하지 못한 채 두 번 고치게 된다.

## 미해결 · 남은 위험

- `scripts/phase6-suite.js`(`P6-FR-K1-RESTORE`, `P6-FR-K2`, `P6-FR-N6A`)와
  `scripts/phase7-suite.js`(`P7-FR-A1`), `scripts/v02-phase4-suite.js`,
  `scripts/v02-phase7-suite.js`는 `Open Folder`가 이제 교체가 아니라 추가라는 사실과
  어긋나는 개별 단언을 여전히 가지고 있다 — TypeError로 죽지는 않지만(호환 shim으로
  해결) 일부 단언은 실패한다. **Phase 6(WK-110)에서 D-3 반전에 맞춰 정리하는 것으로
  남겨 둔다.**
- 표시 별칭(D-4)이 `(N)` 슬롯에 미치는 영향(별칭 지정 시 즉시 반납, 해제 시 재획득)은
  Phase 2(WK-090·WK-091)의 몫이며 이번 회차에서 검증하지 않았다.
- 레일 세로 드래그 정렬·hover `×`·레일 세로 스크롤은 Phase 2(WK-088·089·092) 범위다.
