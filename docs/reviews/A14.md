## 2. 1회차 지적과 처리

### R1-1 (Major) — VS Code Icons SVG가 색 테마를 무시한다

- **지적**: SVG는 fill이 박혀 있어, `VS Code Icons` 아이콘 테마일 때 색 테마를 바꿔도 파일 ·
  폴더 SVG 색이 안 바뀐다. 뷰 액션만 바뀐다.
- **처리**: **수정했다.** `style.css`에 `[data-theme="gray"] .tree-icon.svg-icon svg { filter:
  brightness(0.72) saturate(1.15) }` — 중간 톤 배경에서 색색 SVG가 묻히지 않게. 라이트는 벤더
  자체 light 변형 SVG를 이미 쓰고, 다크는 기본. `V2P6-FR-X10`이 **두 아이콘 테마 모두** 검사한다
  (seti는 색 계산, vscode-icons는 뷰 액션 색 + SVG 렌더가 테마마다 안 같음 + 회색 필터 존재).

### R1-2 (Major) — `.tree-list { overflow-x: hidden }`이라 가로 스크롤바가 못 나온다

- **처리**: **수정했다.** `.tree-list`를 `overflow: auto`(두 축)로. `V2P6-FR-X11`이 두 축 다
  `!== 'hidden'`, `::-webkit` 규칙이 `width`·`height` 다 지정, 트리가 실제로 세로 넘침(파일 40개),
  `scrollTop` 설정이 실제로 움직임을 확인한다. (긴 이름은 VS Code 탐색기처럼 말줄임하지
  가로 스크롤하지 않으므로, 축이 안 막혔고 나오는 바가 테마색이면 충족.)

### R1-3 (Major) — 색 테마 전환이 임시 상태를 지운다

- **지적**: 색 테마 변경 시 `tree.render()`가 인라인 입력 행 · 포커스 · 스크롤 위치를 날린다.
- **처리**: **수정했다.** `TreeController.refreshThemeColors()` — 보이는 각 행의 아이콘 색을 다시
  풀어 **구조를 안 건드리고** 제자리에서 다시 칠한다(`data-fg` + `style.color`). `main.ts`가
  `render()` 대신 이걸 부른다.

### R1-4 (Major) — 스위트 위양성

- **처리**: **수정했다.** `FR-X10` 두 아이콘 테마 검사. `FR-X11` 실제 세로 넘침 + 실제 스크롤.
  `FR-X12` 리졸버가 고른 키(`d.iconName`)에 대해 **참조 seti 데이터**가 정의한 글리프와 정확히
  일치, 세 키가 서로 다름. `FR-X13` 실제 벤더 `<svg>`(`<path>`, >80자) · `iconPath` 이름 있음 ·
  파일 ≠ 폴더 · 열린 폴더 ≠ 닫힌 폴더 · 트리가 `<svg><path>` 렌더. `FR-D2` Electron 러너가
  **실제 `win.maximize()`/`unmaximize()`** 후 다섯 값 재측정.

## 3. 2회차 지적과 처리

### R2-1 (Major) — VS Code Icons가 라이트/다크를 구분 안 한다

- **지적**: 벤더에 top-level `light` 키가 없어 라이트·다크가 같은 SVG. 회색만 필터.
- **처리**: **수정했다.** 세 테마 각각에 **서로 다른** `filter`를 건다 — 라이트
  `brightness(0.9) contrast(1.05)`, 회색 `brightness(0.72) saturate(1.15)`, 다크 없음.
  `V2P6-FR-X10`이 세 `filter` 문자열이 모두 다름 + 렌더된 `<path>` fill이 진짜 색(검정 아님)임을
  확인한다.

### R2-2 (Critical급 Major) — CSP가 참조 SVG의 색을 벗긴다

- **지적**: 벤더 SVG의 ~75%가 색을 인라인 `style="fill:#…"`로 넣는데 이 앱 CSP가 그것을
  벗겨, 그 아이콘들이 색 없이 렌더된다.
- **처리**: **수정했다.** `vscode-icons.ts` `inlineStyleToAttrs()`가 모듈 로드 때 모든 SVG의
  `style="prop:val;…"`를 **표현 속성**(`fill="…"` 등, CSP가 안 건드림)으로 다시 쓴다. 글리프와
  참조 색은 그대로. `V2P6-FR-X13`이 svgData에 `fill="#…"` 속성 있음 · `<… style=…>` 0건 ·
  렌더된 path가 진짜 색으로 계산됨을 확인한다.

### R2-3 (Major) — 스위트가 여전히 불완전

- **처리**: **수정했다.** `FR-X11`이 아주 긴 파일명 하나를 심어 트리가 실제로 **가로**로도
  넘치게 하고(`scrollWidth > clientWidth` + `scrollLeft` 이동 확인, 두 축 다). 이를 위해
  `style.css` `.tree-row { min-width: 100%; width: max-content }` · `.tree-label { flex: 0 0 auto }`
  (말줄임 제거) — 긴 이름이 행을 늘려 VS Code 탐색기처럼 가로 스크롤, 짧은 행은 폭을 채워
  선택 배경이 온전하다.

프롬프트는 검사 · Electron · Python을 돌리지 말고 정적으로만 검토하라고 명시했다(A10~A13에서
검토자가 검사를 돌려 창을 남긴 일이 있어).

## 5. 3회차 지적과 처리

### R3-1 (Major) — 라이트 전용 SVG가 색 테마 전환에 안 바뀐다

- **지적**: `refreshThemeColors()`가 `data-fg` 요소만 갱신하고 SVG는 안 바꿔서, 벤더 라이트
  변형이 있는 파일(`agents.md` 등)이 다크→라이트에서 다크 SVG + 필터로만 남는다.
- **처리**: **수정했다.** `refreshThemeColors()`가 SVG 행도 다시 풀어, `desc.svgData`가 바뀌었으면
  `.tree-icon.svg-icon`의 innerHTML만 교체한다(행 구조 · 포커스 · 스크롤 그대로).
- **검증**: `V2P6-FR-X10`에 `agents.md` 행이 다크→라이트에서 SVG 마크업이 실제로 바뀜을 확인
  (`lightVariantSwapped`).

### R3-2 (Major) — `<style>` 블럭 쓰는 SVG는 CSP 변환에서 빠진다

- **지적**: `inlineStyleToAttrs()`가 `style="…"` 속성만 고치고, `<style>.s1{fill:…}</style>` +
  `class="s1"` 방식(8개 자산)은 그대로라 CSP에 막힌다.
- **처리**: **수정했다.** `<style>` 블럭도 파싱해 `.cls{decls}` 규칙을 `class="cls"` 요소의
  표현 속성으로 옮기고 `<style>` 블럭을 지운다.
- **검증**: `V2P6-FR-X13`이 파일 종류 표본 전부에 대해 `<… style=…>` **와 `<style>` 블럭이 0건**임을
  확인. 렌더된 fill이 `rgb(0, 122, 204)`(TypeScript 파랑) 등 진짜 색.

### R3-3 (Major) — `scrollbar-color`가 있으면 Chromium이 `::-webkit-scrollbar`를 무시한다

- **지적**: non-`auto` `scrollbar-color`를 주면 현대 Chromium이 `::-webkit-scrollbar*` 의사요소를
  통째로 무시한다. 그래서 hover · active 토큰이 스크롤바에 안 닿는다.
- **처리**: **수정했다.** `scrollbar-color` 축약형을 없애고 `::-webkit-scrollbar*`로만 스타일한다
  (rest · hover · active 다 나온다). 두 갈래 다 Chromium이라 Firefox 전용 표준 속성은 필요 없다.

### R3-4 (Major) — `FR-D2`가 시스템 배율 변경을 안 본다

- **처리**: **수정했다.** Electron 러너가 `win.webContents.setZoomFactor(1.5 / 0.8 / 1.0)`으로
  시스템 배율 변경을 흉내내고 다섯 값이 각각 30 CSS px 그대로임을 확인한다(실제 maximize/restore도).

## 7. 사람 확인 사항

- **`FR-X10` ↔ `FR-X13` 긴장**: vscode-icons SVG는 "참조 구현과 같은 SVG"(`FR-X13`)라 색이
  박혀 있는데, "모든 아이콘 색이 따라 바뀐다"(`FR-X10`)를 만족시키려 테마별 CSS `filter`를
  건다. 마크업은 그대로, 렌더된 색만 바뀐다. 필터 세기(라이트 `0.9`, 회색 `0.72`)는 사람의
  눈으로 최종 판정할 몫이다.
- **seti 회색 파일 아이콘 대비**: 회색 배경(#7d7d7d)에서 중간 톤 파일 색은 대비가 낮다(측정값
  일부 1.4 근처). `darkenHex(...0.5)`로 밀었으나 사용자 재검증에서 특정 파일 종류가 안 보이면
  seti 회색 계산을 더 조정해야 한다.
