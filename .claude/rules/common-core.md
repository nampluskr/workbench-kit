# 공통부 — 앱별 리소스 지식이 새는 사고를 막는다

이 규칙이 막는 사고: 특정 파생 앱만의 "파일이란 무엇인가"를 아는 코드가 공통부에
들어와, 다음 앱이 같은 베이스 앱을 못 쓰게 되는 것.

**INTENT 3절이 2026-09-25에 바뀌었다.** 베이스 앱은 stand-alone 앱이고 필수·공통
기능을 구현해 둔다. 그 필수·공통 기능은 리소스 종류를 알더라도 공통부에 둘 수 있다.
그 밖의 코드는 예전 규칙 그대로다.

**대상 경로** — `src/core/`. 앱·프리셋·시험 코드는 제외.

## 허용 목록 — 리소스 종류를 알아도 공통부에 두는 필수·공통 기능

| 기능 | 근거 |
| --- | --- |
| 마크다운 렌더링 — `src/core/markdown/` 한 폴더(렌더러·정화·수식·코드 강조·rendered 보기·토글 설정·`.md` 열기 연결) | INTENT 1·3절 · v0.4 `DECISIONS.md` D-11 |

허용은 **그 폴더 안**에만 적용된다. `src/core`의 다른 파일(예: Activity Bar에 더하는 SVG
아이콘 경로)은 여전히 리소스 종류를 모르는 범용 장치로 만든다.

목록에 없는 기능을 공통부에 넣으려면 먼저 사람이 이 표에 더해야 한다. 에이전트가
스스로 더하지 않는다.

## 하지 않는다 (허용 목록 밖의 코드)

- 확장자 → 아이콘·언어·보기 종류 대응표를 둔다 (`FR-Q3` · `NFR-1`)
- 파일·폴더·터미널·세션이라는 낱말로 분기한다 (`INTENT.md` 3절 · D-4)
- 파일을 만들거나 이름을 바꾸거나 지운다. 공통부는 장치만 준다 (D-30 · D-22)
- 저장을 한다. 공통부는 ● 표시와 확인 창까지다 (D-18 · `FR-P7`)
- 앱에게 탭·칸을 만들거나 닫거나 옮기는 수단을 연다 (`FR-I8` · C-9)
- 갈래(Electron · pywebview) 이름으로 분기하는 빌드 설정을 만든다 (D-25 · `NFR-2`)
